# Agent Evidence — 주장 전 증거 확보 규칙

Agent가 사실을 주장할 때는 반드시 **명령 실행 결과**를 근거로 삼는다. 읽지 않고, grep 하지 않고 단정하지 않는다.

## 금지

- "X는 없음" / "0개 감지" / "구현 안 됨" 같은 절대 진술을 근거 없이 쓰지 않는다
- "아마 ~일 것" / "~로 추정" 같은 모호한 주장으로 결론을 대체하지 않는다
- 코드 경로·파일 존재 여부·함수 시그니처를 **기억으로** 말하지 않는다

## 요구

- **존재 여부**: `Glob` 또는 `ls` 결과를 인용
- **사용 위치**: `Grep` 명령 + 히트한 파일·라인 인용
- **행동 흔적**: `git log` / `git diff` 경로 제시
- **수치 주장**: 실행 명령 + 결과 수치 그대로 옮김 (예: `rg -n "pattern" | wc -l` → "N hits")

## 결과 부재일 때

- "확인되지 않았다 (명령 + 조건)" 톤을 기본으로 쓴다
- "없다"는 결론은 **negative 검증 시도 + 그 범위 명시** 이후에만 내린다
- 정보가 확실하지 않으면 사용자에게 질문하거나 조사 범위를 추가 노출한다

## 변경·상태 주장 (diff 읽기) — 오독 방지 (MUST)

"이 파일이 바뀌었다 / 키가 제거됐다 / 외부가 건드렸다 / 보안 이상" 같은 **변경 주장**은 특히 오독하기 쉽다(2026-07-04 `settings.json` 오경보 사건 — canon `managed-artifacts.md`). 강제:

- **구조화 파일(JSON/YAML/lockfile/재정렬된 파일)의 diff 는 line-diff 로 단정하지 않는다.** 포매터(biome `--write` 등)가 키 순서만 바꿔도 line-diff 는 대량 `-/+` 로 보인다. 반드시 **key-level 의미 비교**: `bun run json-diff <file> [ref]`. "키 제거/추가" 는 key-level 결과로만 말한다(빈 델타 = 포매팅 churn).
- **truncated diff(`| head`)로 결론 금지.** 판단 근거 diff 는 전체를 보거나 요약 도구를 쓴다.
  ⚠ **그리고 이건 diff 만의 규칙이 아니다** — 아래 「판단 근거를 자르지 않는다」로 일반화됐다.
- **에이전트-관리 파일**(`settings.json`·`settings.local.json`·`.mcp.json`·`biome.json`·lock·`memory/*`·CLAUDE.md sync 구간·`ecosystem.json packages`)의 세션 중 diff 는 **예상된 자동 churn** — 외부/침해/회귀로 단정하기 전 key-level + 이번 세션 에이전트 행위(편집·`--apply`·포맷)의 부산물인지 대조(카탈로그 = `managed-artifacts.md`).
- **사용자 경보(⚠) 전 반증 1스텝** — "제거됨/유실/외부 변경/보안 이상" 은 disconfirming 체크를 통과한 뒤에만, **근거 명령 결과를 인용해서** 발화한다. 근거 없이 "확인 필요"로 사용자를 놀라게 하지 않는다("고장 주장에도 증거" — 완료=증거의 쌍대, `knowledge/journal/20260703-fleet-completeness-session.md`).

## 초록불 주장 — **무엇이 통과했나가 아니라 무엇을 실제로 검사했나** (MUST)

게이트가 초록이라는 것은 **"검사가 통과했다"** 는 뜻이지 **"그것이 검사됐다"** 는 뜻이 아니다.
빈 대상 · 좁은 스코프 · 관대한 스텁 · 잘못된 입력은 **전부 통과로 위장한다.**

실사례 (modfolio-design 2026-07-27 실측 4건 + 이 저장소 실측):

| 무엇이 초록이었나 | 실제로 검사한 것 |
|---|---|
| axe "위반 0" | 컨텍스트를 `document.body` 로 줘 `landmark-one-main`·`page-has-heading-one` 이 **스코프 밖**. h1 이 없는 페이지가 통과 |
| 배포 검증 "이상 없음" | `preload` 제거로 스캔 대상이 **0건**이 됐는데 0건을 통과로 읽음 |
| 로컬 테스트 통과, 프로덕션 500 | 스텁이 **가변** Response 를 반환, 실제 바인딩은 **불변** |
| 4스택 parity 통과 | 픽스처가 prop **타입**을 몰라 넷이 **똑같이 틀렸다** |
| "quality:all 1054 pass" | `grep "N pass"` 는 **테스트 개수**이지 게이트 결과가 아니다. `check` 가 exit 1 인데 `&&` 로 중단돼 이전 실행 숫자를 읽고 green 보고 |
| 게시 성공 | 백필 실패가 한 줄 warn 이고 **이유가 잘려**(npm 매니페스트가 800자 예산을 다 씀) 매 릴리즈 조용히 실패 |

### 두 번째 부류 — 대상도 있고 검사도 도는데 **기준이 틀린** 경우 (2026-07-27 인바운드)

위 표는 전부 "검사 대상이 비었거나 좁거나 가짜" 였다. 다음은 다르다 — **대상은 진짜고 검사도
정상 실행된다. 정답으로 삼은 것이 결함이다.** 그러면 게이트는 결함을 *지킨다*.

| 무엇이 초록이었나 | 정답으로 삼은 것 | 출처 |
|---|---|---|
| 결제 화면 시각 회귀 통과 | 베이스라인 PNG 가 **"500 / Payment configuration error"** 화면. 에러를 에러와 비교하며 계속 초록 — 나중에 진짜 수정이 **회귀로 잡힌다** | pay |
| `client_credentials` 스코프 스펙 통과 | 스펙 문장이 *"unrestricted key(no scopes) 는 요청 스코프를 허용한다"* — **요구사항이 아니라 구현을 보고 쓴 테스트**. fail-open 이 명세가 됐다 | connect |
| `createApiKey` 유닛 스펙 통과 | **스펙을 소비자로 셌다.** 실제 프로덕션 호출자는 0(`api_key` 0행) — 기능은 완결됐고 **문이 없었다** | connect |
| 프로필 페이지 정상 | UI 가 `<span>Verified</span>` **리터럴**. 읽지도 않은 상태를 단언 → 없는 "인증" 버튼이 필요 없어 보였다 | connect |
| a11y 22/22 통과 | 런타임이 `each_key_duplicate` 를 **던지고** 있었고 그 예외를 보는 단언이 없었다 | pay |

**공통 형태**: 검사는 성실히 도는데 *무엇이 옳은가*를 산출물·구현·표시문자열에서 역산했다.
산출물에서 명세를 역산하면 **결함이 명세가 된다** — 허브가 "게이트가 저자 의도가 아니라
포매터 출력을 검사하고 있었다" 로 겪은 것과 같은 뿌리다(connect 가 그 연결을 지적했다).

### 세 번째 부류 — **검사를 만족시키는 가장 싼 방법이 의도한 작업이 아닐 때** (2026-08-03 modfolio-pay)

앞 두 부류는 *대상*이나 *정답*이 틀렸다. 이건 다르다 — 대상도 정답도 맞는데 **통과
조건이 저자의 의도가 아니라 그 의도의 가장 싼 대리 지표**다. 그래서 이 게이트들은
**정직하게 실패도 한다**(빈 스캔도 0건도 아니다). 작동하는 게이트처럼 보이는 것이
이 부류의 특징이다.

- **"그 파일이 X 를 언급하는가" 는 언급만으로 통과한다.** 실측: 아키타입 계약 검사가
  `expect(source).toContain('archetype/…svelte')` 하나였다 — 24화면에 import 21줄만
  붙이면 **화면을 한 픽셀도 안 고치고** 초록이 된다. 하필 *"아무도 import 하지 않으면
  그건 주장이지 형태가 아니다"* 를 막으려고 만든 게이트 안에 있었다. → 검사를 쓸 때
  **"이 조건을 만족시키는 가장 싼 방법이 무엇인가"** 를 묻고, 그게 의도한 작업이
  아니면 **렌더/런타임 짝**을 붙인다(마크업에 실제로 있는가 · 라이브 DOM 에 있는가).
  ⚠ biome 의 unused-import 는 `.svelte` 템플릿 안을 보지 않아 import 만 남기는 것이
  실제로 가능하다.
- **`var(--x, fallback)` 은 아무도 `--x` 를 안 줘도 에러가 없다 — 기능만 사라진다.**
  실측: `.mp-stagger` 가 자식마다 `--i * 40ms` 지연을 주는데 **앱 어디에도 `--i` 를
  넣는 코드가 없어** 전 자식이 0ms 였다. 고장처럼 안 보이고 **그냥 페이드로 보인다.**
  직전 인계 문서가 *"이 동작을 조용히 잃지 마라"* 라고 경고하고 있었는데 **일어나지도
  않던 동작을 보호하고 있었다.**
  ⚠ **다만 SET 이 0건이라고 전부 결함은 아니다** (atelier 2026-08-04, 이 스윕을 자기
  저장소에 돌려 보고 정정). **폴백이 무엇을 낳는가**로 갈린다:

  | 폴백이 낳는 것 | 판정 |
  |---|---|
  | **선언된 동작의 부재** — 지연·오프셋·애니메이션이 «그냥 안 일어남» | **결함.** 고장처럼 안 보이고 «원래 그런 디자인» 으로 보인다 (pay `--i`: 전 자식 0ms) |
  | **올바른 기본값** — 훅은 오버라이드용이고 폴백이 곧 정답 | **정상** (atelier `--pill-bd`: 폴백이 그 앱의 기본 테두리색. 랜딩에선 실제로 SET 한다) |

  판별 질문: ***"이 프로퍼티를 아무도 안 주는 지금, 사용자가 보는 것이 의도된 상태인가?"***
  이걸 안 붙이면 스윕이 **미사용 확장점을 전부 결함으로 보고**하고, 오버라이드 훅에 폴백을
  두는 **좋은 CSS 관행을 벌한다**(「과탐이 규약 준수를 벌한다」와 같은 축). → 클래스 유무가 아니라 **계산된 값**(`animation-delay`
  등)을 단언한다. 스윕 한 줄: `rg -o -- '--[a-z-]+, *[0-9a-z]' src | sort -u` 로
  폴백 있는 커스텀 프로퍼티를 뽑고, 각각을 **SET 하는 곳이 있는지** 확인.
- **사용자에게 스위치를 주고 아무도 읽지 않는다.** 실측: 알림 설정이 토글 10개를
  보여주고 저장하고 다시 그렸는데 **보내는 쪽은 한 번도 읽지 않았다** — "결제 완료"
  를 꺼도 메일이 그대로 나갔다. 10개 중 2개는 **끌 대상 자체가 없었다**(템플릿·호출부
  0). 아무것도 실패하지 않은 이유: UI 쪽과 발신 쪽이 **각자 내부적으로는 일관**됐고
  둘이 만나는 지점이 없었다. → 키 목록을 하나로 모으고 **양방향 JOIN 게이트**:
  스위치는 있는데 게이트가 없으면(=장식) 실패, 게이트는 있는데 스위치가 없으면(=끌 수
  없음) 실패. **동작하는 옵트아웃을 보여주고 무시하는 것은 기능 누락보다 나쁘다 —
  사용자에게 사실이 아닌 것을 말한 것이다.**
- **`fullPage: true` 가 app-shell 레이아웃에서는 무동작이다.** `height: 100dvh` +
  안쪽 `overflow:auto` 면 **문서가 절대 스크롤되지 않아** 늘릴 높이가 없다. 실측:
  베이스라인 17개 전부가 정확히 뷰포트 크기였고 **접힌 윗부분만 검증하면서 "전체"라고
  주장**하고 있었다(스펙 주석이 *"long-page 도 전체 캡쳐"* 라고 적어 둔 채). 확인법:
  산출물 PNG 높이가 전부 뷰포트 높이와 같으면 `fullPage` 가 안 먹고 있는 것이다.

추가로 같은 날 올라온, **검사가 아예 안 돌던** 형태 셋:

- **테스트 스크립트가 디렉터리로 좁혀져 있었다** — `"test": "bun test server"`. `server/` 밖
  테스트는 작성해도 **러너가 보지 않는다.** "검사가 약한" 게 아니라 **없는** 것이라 더 위험하다.
  새 테스트를 넣었는데 총계가 안 늘어서 발견됐다 (atelier)
- **게이트 트리거 목록에 그 게이트 자신이 없었다** — a11y 트리거가 `apps/app/src/**` 만 봐서
  a11y 스펙·fixture·config 를 고치는 push 는 **그 스위트를 안 돌리고** 나갔다 (pay)
- **마스크 셀렉터가 0개를 매칭하면 조용히 무력화**되고 스크린샷은 계속 초록이다가 어느 날
  갑자기 깨진다 — 셀렉터가 실제 요소를 잡는지 확인하는 테스트가 따로 필요하다 (pay)

### 요구

- **게이트 결과는 exit code 로 판정한다.** 출력 문자열(`N pass`, `no errors`)은 결과가 아니다.
  `bun run <gate> >/dev/null 2>&1; echo $?`
  ⚠ **판정할 명령이 복합문의 마지막이 아니면 종료코드는 남의 것이다.** 파이프만의 함정이
  아니다 — `;` · `tee` · `|| true` · `&& echo ok` 가 전부 같은 축이다(connect 2026-08-03 이
  파이프 규칙을 일반화해 보내왔다). 세 얼굴:
  - `bun run gate | tail -5; echo $?` → `tail` 의 0 (pay 2026-07-28)
  - `git push > log 2>&1; echo "EXIT=$?" >> log` → **`$?` 는 맞게 찍히는데 그 명령 자체의
    종료코드는 `echo` 의 0 이다.** 하네스·CI 가 그걸 보면 **실패를 성공으로 읽는다** —
    connect 는 그렇게 실패한 푸시를 "completed" 알림으로 받았고 로그 안의 `PUSH_EXIT=1` 을
    못 봤다. 사람이 읽는 값과 기계가 읽는 값이 갈린다.
  - `cmd 2>/dev/null | head || fallback` → `||` 가 파이프의 0 을 봐서 **폴백이 안 돈다**.
    남는 건 빈 출력이고 그게 "델타 없음" 으로 읽힌다(athsra 2026-08-03, 아래 「멤버가 못 도는
    MUST」와 겹쳐 발생).

  판정할 명령을 파이프·후행절 없이 돌리거나 `PIPESTATUS`/`pipefail` 을 읽어라.
- ⚠ **`cmd | grep -q` 는 «매치했는데 안 한 것처럼» 동작할 수 있다 — 그리고 검사가 반대로
  붙어 있으면 그게 «거짓 초록»이 된다** (허브 2026-08-05 자기 스크립트에서 실측).
  `set -o pipefail` 아래서 `grep -q` 는 **첫 매치에서 즉시 종료**한다. 왼쪽 명령이 아직 쓸
  것이 남아 있으면 **SIGPIPE 로 죽어 파이프라인 상태가 141** 이 되고, `&&` 는 실패한다.

  ```
  OUT="Feedback: written to …/node_modules/…"$'\n'"<300KB>"
  echo "$OUT" | grep -q "written to.*node_modules"   → 파이프라인 상태 141
    && note_fail …   ← 실행 안 됨
    || note_ok  …    ← **실행됨. 진짜 결함이 초록으로 보고된다**
  ```

  이 저장소의 published-canary 가 정확히 그 형태였고, 하필 **거짓 초록 쪽**이 2026-07-27
  실사건(매니페스트가 `node_modules` 안에 쓰여 다음 설치에 지워짐) 때문에 만든 체크였다.
  같은 파일의 다른 두 곳은 반대로 붙어 있어 **거짓 빨강**이 된다 — 매 릴리즈 반복되면
  사람을 «무시하도록 훈련»시킨다(infra: *"거짓 음성은 노이즈보다 나쁘다"*).

  ```
  rg -l NEEDLE (DEVNULL)  → exit 0 · a.txt probe.py
  ```

- ⚠ **정규식이 «통과 방향»으로 고장 날 수 있다 — `(?!…)` 를 가변 길이 뒤에 놓지 마라**
  (modfolio-notify 2026-08-05 제보, 허브 재현). 앞의 두 항이 «도구가 출력을 바꾼다» 라면

  허브 재현 — **공백 유무로 갈린다**:

  ```
  outline: none        → 매치      ← 틀렸다. 대체가 없는데 «있다» 로 읽는다
  outline:none         → 매치 안 됨 ← 맞다
  outline: 2px solid   → 매치       (정상)
  box-shadow: 0 0 2px  → 매치       (정상)
  ```

- **선언·목록·문서는 실물과 대조되기 전까지 주장이다.** 앞의 항목들이 *검사*의 실패를
  다뤘다면 이건 그 **앞단**이다 — 아예 검사 대상으로 등록된 적이 없는 사실들. 셋은 서로
  다른 곳에서 같은 방식으로 썩는다. 실측 2026-07-31, modfolio-infra 가 하루에 세 개를
  독립적으로 찾아냈다:
  - **목록**: 리댁터 `SECRET_PATTERNS` 에 athsra device token(`atk_`)만 있고 service
    token(`ats_`)이 없었다. 그런데 그 머신의 `~/.athsra/remote-tokens/` **34개가 전부
    `ats_` 이고 `atk_` 는 0개** — 즉 **안 쓰는 계열만 덮고 실제로 쓰는 유일한 계열은
    못 보고 있었다.** 목록은 원리적으로 "이미 아는 것"만 덮으므로, 목록 옆에는 **모양
    기반 검출**을 같이 둔다.
  - **선언**: `ecosystem.json.harnessLatest`. release-gate 는 `package.json` ==
    `ecosystem.json` == `plugin.json` **세 사본이 서로 같은지**만 봤다 — 셋이 사이좋게
    **존재하지 않는 버전**에 합의할 수 있고, 그동안 fleet 배너는 설치 불가능한 버전을
    매 세션 안내한다(안내대로 해도 아무 일이 없으니 **고칠 수 없는 지시의 영구 반복**).
    사본끼리의 일치는 정합이 아니다. **실물(레지스트리)과 대조**해야 한다.
  - **문서**: canon 이 "자유 phrase 도 된다" 를 설명하며 **그럴듯한 12자 문자열**을 예시로
    들었고, 그게 저널로 번져 게시본 9파일 30곳에 실렸다(공개 npm). 그리고 그 문자열이
    **실제 자격증명으로 쓰이는 지점이 발견됐다** — 문서가 품질 문제가 아니라 **하류 결함을
    생산**했다. 접두사도 엔트로피도 없어 어떤 시크릿 패턴에도 안 걸린다.
  → 셋 다 **대조 상대를 지정하는 것**이 수정이다: 목록↔실사용 · 선언↔레지스트리 ·
  문서↔자리표시자 규칙. 그리고 그렇게 만든 검사는 **실물로 대조쌍을 세운다** — 이 문서
  게이트는 합성 픽스처였으면 통과했을 자리에서 창시 사례를 놓쳤고(문맥이 줄이 아니라
  **감싸는 제목**에 있었다), `git show` 로 꺼낸 수정 전 실물로 잡았을 때만 걸렸다.

#### **«이미 대응했다» 는 «지금도 대응돼 있다» 를 보장하지 않는다** (2026-08-04 connect → 허브 실측)

위 항목들은 전부 «선언이 실물과 다르다» 였다. 이건 **선언이 옳았던 적이 있다** — 그리고
아무도 손대지 않았는데 거짓이 됐다. 대조 상대가 **바깥에서 움직이기 때문**이다.

connect 실측: 이전 CVE 때문에 `brace-expansion` 을 `^2.1.2 || ^5.0.8` 로 이미 핀해 뒀는데,
**mitigation 을 우회하는 후속 advisory**(GHSA-rgw5-rvv9-x895)의 범위가 `>=4.0.0 <5.0.9` 라
**그 핀 자체가 범위 안**이었다. 기록은 «대응 완료» 라고 말하고 있었다.

허브가 이 노트를 등재하려고 자기 저장소를 열었더니 **같은 것이 그 순간 진행 중이었다**:

```
40분 전  quality:all  exit 0            ← check:audit 포함, 취약 0
지금     check:audit  exit 1  (high 2 · moderate 1)

fast-uri  >=4.0.0 <4.1.2   ← 우리 overrides 는 "^4.1.1" (이전 advisory 대응)
undici    >=7.0.0 <7.29.0  ← 우리 overrides 는 "^7.28.0" (이전 advisory 대응)
```

**코드도 lockfile 도 안 건드렸는데 빨개졌다.** 두 핀 다 «대응했다» 의 산물이었고, 새
advisory 범위가 **정확히 그 대응값을 포함**했다. 4.1.2 · 7.29.0 으로 올려 0 으로 닫았다.

**왜 이 형태가 조용히 유지되는가 — 「핀은 바닥을 정하지 천장을 밀지 않는다」** (athsra 2026-08-04).
대응으로 `^3.1.3` 을 적어 두면 **위로는 열려 있지만 lockfile 은 이미 3.1.4 에 고정**돼 있다.
아무도 `bun update` 를 돌리지 않으면 **영원히 3.1.4** 이고, 그 사이 새 advisory 범위가
`>=3.0.0 <3.1.5` 로 올라오면 그 핀은 «대응» 이 아니라 **취약본을 고정하는 장치**가 된다.
캐럿은 의도를 적은 것이지 값을 민 것이 아니다.

> **가장 아픈 형태는 이전 advisory 대응으로 넣은 핀이 다음 advisory 를 잡아 두는 것이다.**
> `^3.1.3` 은 «3.1.3 이상» 이라 안전해 보이지만, 락이 3.1.4 에 있으면 3.1.5 로 갈 이유가
> 아무 데도 없다. **핀을 넣은 사람은 자기가 보호막을 쳤다고 기억하고, 그게 감옥이 된다.**
> (athsra 2026-08-04)

→ 요구:
- **예외·핀·mitigation 기록은 «누가 언제 왜» 만이 아니라 «어떤 범위에 대해» 를 적는다.**
  범위가 없으면 후속 advisory 와 대조할 수가 없고, 그러면 재검토는 사람의 기억에 달린다.
- **감사 게이트는 «지난번에 0이었다» 를 근거로 건너뛰지 않는다.** 이 축의 대조 상대는
  저장소 밖(advisory DB)에 있고 **우리 커밋과 무관하게 움직인다** — 위 「배포 대상이 저장소
  밖에 있다」(sign)와 같은 형태이며, 그래서 게이트가 **매번** 실물을 물어야 한다.
- `revisit_after` 날짜는 **하한**이지 판정이 아니다. 날짜가 안 왔어도 범위가 겹치면 그 예외는
  이미 무효다.

### 네 번째 부류 — **뒤집어도 아무것도 안 깨지는 불변식** (2026-08-03 modfolio-pay)

앞 세 부류는 전부 *"검사가 무언가를 잘못 본다"* 였다. 이건 **볼 것이 애초에 없다.**

실측: pay 에 사업자가 둘이 됐고(모드폴리오 + 에이앤에프), 전금법상 크레딧이
**발행인 외의 제3자에게서 쓰이면** 자기발행형 선불이 아니라 선불전자지급수단이 되어
**이미 판매된 크레딧 전부에 소급으로** 선불업 등록이 요구된다. 그래서 코드에 필드를 뒀다:

```ts
readonly acceptsCredits: boolean;   // 발행인만 true
```

**이 플래그를 뒤집으면 아무 기능도, 화면도, 다른 테스트도 안 깨진다. 제품이 법적으로
무엇인지만 바뀐다.** 타입도 린트도 게이트도 원리적으로 볼 것이 없다 — 그래서 *"한 명만
true"* 를 단언하는 **테스트가 유일한 방어**다.

→ **규칙**: 값을 바꿔도 동작이 그대로인데 **법적·계약적·안전상 성질만 바뀌는 상수·
플래그·목록**은 반드시 단언한다. 판별 질문 한 줄: *"이걸 잘못 설정하면 무엇이
실패하는가?"* — 답이 **"아무것도"** 면 그 자리가 테스트가 필요한 자리다. 주석은 방어가
아니다(주석은 실행되지 않는다).

같은 형태가 이 universe 에 더 있다: 소비 좌표 단일 원칙(`registry-redundancy`) ·
consent 게이트(`knowledge-sovereignty`) · `minTier`(로컬 레일에 넘기면 안 되는 task
class) — 전부 틀려도 초록이 나온다.

### 발신 경계의 스키마는 **생산자보다 엄격하면 안 된다** (2026-08-03 허브 자기정정)

공유 이벤트 스키마를 등재하면서 필드 **이름**은 생산자 원문에서 가져왔는데 **제약은
지어냈다** — `refund_amount: z.number().positive()` · `currency: z.enum([...])`.
생산자 실물은 `z.number()` · `z.string()` 이었다.

이게 왜 위험한가: 그 생산자의 `publishEvent` 는 `safeParse` 실패 시 이벤트를
**DROP** 한다(아웃박스에 도달조차 못 한다). 더 엄격한 공유 스키마를 채택하는 순간
**구조적으로 멀쩡한 정산 이벤트가 조용히 사라진다.** 생산자가 금액을 `z.number()` 로
두는 것은 느슨해서가 아니라 **불변식을 원장 소스에서 강제하고 이벤트 경계에서 재단언
하지 않기 때문**이다 — 재단언이 곧 drop 위험이다.

그리고 그 발명 위에 *"0원 환불은 이벤트가 아니다"* · *"없는 통화는 거부"* 라는 테스트를
붙여 **발명을 정답으로 굳혔다**(위 「두 번째 부류」 그대로, 이번엔 허브 자신이).

→ **원칙**: 공유 스키마는 **생산자가 실제로 내보내는 것**을 기술한다. 그보다 좁으면
계약이 아니라 희망이고, 그 희망이 데이터를 삼킨다. 더 강한 보장이 필요한 소비자는
**자기 쪽에서 좁힌다**(수신 엄격 · 발신 관대 — 방향이 반대면 안 된다).
⚠ 관대함이 "아무거나 통과" 는 아니다. 타입·구조는 여전히 거부한다.
⚠ enum 을 발신 경계에 박으면 값 하나 추가가 published 패키지의 breaking bump 가 되고,
그 사이 그 값의 트래픽은 전부 유실된다.

### census 는 **방향을 뒤집으면 유한해진다** (2026-08-03 modfolio-pay)

*"계약에 없는데 발행되는 이벤트"* 를 잡으려고 **생산자 코드를 세면** 리터럴·동적 조립·
조건부 발행을 계속 놓친다(pay 2026-07-27 실측: 상수 참조만 세어 **리터럴 발행 16종을
통째로 놓침**). pay 를 구한 것은 census 를 더 똑똑하게 만든 게 아니라 **방향을 뒤집은
것**이다:

| 방향 | 성질 |
|---|---|
| 생산자 코드 → 계약 | 대상이 **무한**하다(코드의 모든 발행 지점). 놓치기 쉽고 오탐도 많다 |
| **계약 유니온 → 발행 코드** | 대상이 **유한**하고 목록이 이미 있다. **0건이 곧 답이다** |

역방향은 *"안 쓰는 계약"* 만 잡고 *"계약에 없는 발행"* 은 못 잡으니 **둘 다** 필요하다.
다만 **유한한 쪽을 먼저 만든다** — 목록이 유한해야 실물 대조가 가능하다.

### 다섯 번째 부류 — **검사 표면이 «배포 대상»을 포함하지 않는다** (2026-08-03 modfolio-sign)

앞의 넷은 전부 *검사가 무언가를 잘못 본다* 였다. 이건 **검사가 옳고, 대상이 저장소 밖에 있다.**

실측: 대시보드를 배포했다. `release:gate`(test·typecheck·build·lint·e2e) **전부 초록**,
`wrangler deploy` **성공**, 라이브 **200**. 그런데 프로덕션 D1 에 마이그레이션이 적용되지
않은 채였고, `/app/+layout.server.ts` 가 `membershipsOf()` 를 부르는 **레이아웃**이라
**로그인한 사용자는 모든 화면에서 500** 을 받았다. *"초대받은 앱이 없습니다"* 화면은
**도달 불가능**이었다.

**왜 아무 게이트도 못 봤나 — 구조적이다.** 타입검사·린트·테스트·빌드는 전부 저장소 안을
본다. 로컬 D1 은 테스트가 매번 스키마를 만들어 주므로 **로컬은 언제나 최신**이다.
프로덕션 스키마는 저장소 밖에 있고, 파이프라인 어디에도 *"프로덕션이 이 코드를 감당하는가"*
를 묻는 단계가 없었다.

> 그 repo 의 인계 문서는 상태를 *"`ms_app_members` **0행**"* 이라고 적고 있었다.
> 실측은 **`no such table`** 이었다. **자기 자신에 대한 진술이 틀렸다** — 「선언은 실물과
> 대조되기 전까지 주장」이 자기 repo 안에서도 성립한다.

**요구**:
- **배포 전** 원격 마이그레이션 원장(`d1_migrations` 등) ↔ 저장소 마이그레이션을 **양방향**
  대조한다. `로컬 ⊄ 원격`(미적용)도, **`원격 ⊄ 로컬`(저장소가 모르는 것이 프로덕션에 있다 —
  더 위험하다)**도 실패다.
- ⚠ **`wrangler d1 migrations list --remote` 를 파싱하지 마라.** 미적용이 있어도 **exit 0**
  이고(sign 실측) ASCII 표는 계약이 아니다. **테이블을 조회**해서 판정한다.
- 이 게이트는 **`release:gate` 가 아니라 배포 명령 앞**에 건다. pre-push 훅이 쓰는 게이트는
  오프라인·무인증에서 통과해야 하기 때문이다. **그 구분이 중요하다.**
- 짝이 되는 **오프라인 축**을 같이 둔다: 코드가 선언한 테이블(`sqliteTable` 등) ↔ 마이그레이션
  **재생** 결과. ⚠ 재생은 **파일 순서대로** — 문장 종류별로 묶으면(CREATE 전부 → RENAME 전부)
  SQLite 테이블 재작성 관용구에서 **테이블이 통째로 증발**한다(sign 실측 5개).
- **런타임 fail-loud 도 유효한 형태다.** 허브 `apps/loom` 은 매 요청 앞에서 기대 테이블 존재를
  확인하고 없으면 **503 + 없는 테이블 이름**을 준다(`no such table` 을 500 으로 흘리지 않는다).
  배포 전 게이트를 대체하진 않지만, 갭이 열렸을 때 **증상을 진단 가능하게** 만든다.

**같은 날 두 번째 얼굴 — 관측 가능한 표면 ≠ 시스템의 표면.** 배포 후 스모크 10건이 전부
통과하는데 로그인 토큰 교환이 401 이었다. 무인증 표면은 완벽히 건강하고 **서버 대 서버 구간**이
깨져 있었다. **브라우저 없이 지나갈 수 없는 구간은 라우트 프로브로 안 보인다** — 그런 구간에는
자격증명 없이 도는 별도 프로브를 찾아 둔다(sign 은 `POST /sso/device_authorization` 이 클라이언트
등록 상태를 세 값으로 구분해 준다는 것을 찾았다).

### **optional + 기본값은 분류를 강제하지 않는다 — 숨긴다** (2026-08-04 modfolio-notify → pay 실측)

어떤 축으로 분류를 강제하고 싶으면 그 필드를 **필수·무기본값**으로 둔다. optional 이면
미분류 항목이 안 걸리고, **기본값이 있으면 미분류가 조용히 한 칸에 몰린다** — 그리고 그 칸이
늘어나는 것을 아무도 안 본다.

실측: pay 가 `EmailKind` 를 **기본값 없는 필수**로 넣자 타입체커가 즉시 갈랐다.

```
배럴이 export 하는 템플릿      12
실제 sendEmail 호출 지점       13   ← weekly-digest.ts (배럴을 안 거친다)
```

*"우리 메일은 12종"* 이라는 **자기 인식이 틀렸다**는 것이 드러났다. pay 자신의 문장:

> *"이 발견은 `kind` 를 optional 로 뒀으면 안 나왔다. 기본값이 있었으면 13번째가 조용히
> 그 값을 물려받고 목록은 계속 12로 보였을 것이다."*

**부수효과가 본래 목적보다 먼저 온다**: 분류를 붙이려던 것인데 **컴파일러가 그 축의 전수
목록을 만들어 준다.** 「선언·목록은 실물과 대조되기 전까지 주장」의 예방형이다 — 대조할
필요가 없게, 타입이 목록을 강제로 완성시킨다.

후보 축(fleet 에 같은 형태가 여럿): 이벤트 종류 · 로그 레벨 · 권한 스코프 · 과금 항목 ·
알림 채널. **판별 질문**: *"이 필드를 optional 로 두면, 분류 안 된 것이 몇 개인지 누가 세나?"*
답이 «아무도» 면 필수·무기본값이 맞는 자리다.

### 짧은 것들 — 같은 축, 각각 실측 1건 (2026-08-03 fleet 라운드)

- **rule 이 처방하는 명령을 멤버가 못 돌 수 있다** (athsra). 이 문서가 `bun run json-diff` 를
  MUST 로 주는데 스크립트는 tarball 에 실려 가고 **배선은 안 갔다** — 멤버에선
  `Script not found` 였다. 그리고 위 「종료코드」 함정과 겹쳐 **조용히** 실패해, 빈 출력이
  "키 델타 없음" 으로 읽힐 뻔했다. → 허브가 `MEMBER_WIRED_SCRIPTS` 로 배선하고
  `verify:rule-commands` 가 대조한다. **rule 은 자기 실행 가능성을 스스로 보증해야 한다.**
- **문서가 canon 이 금지한 것을 가르칠 수 있다** (athsra). 허브의 내부 온보딩 가이드가
  canon 이 이름을 대며 금지한 엔드포인트 직행 + sessionStorage PKCE 를 처방하고 있었다.
  타입도 테스트도 안 보는 표면이라 아무것도 빨개지지 않았고, **새로 붙는 앱이 그대로 구현**했다.
  → canon 이 이름으로 금지한 것이 문서의 **코드 블록**에 나오면 실패하는 검사가 가능하다.
- **`git ls-files` 는 새 파일을 게이트에서 숨긴다** (atelier). 아직 추적되지 않은 파일은
  목록에 없으므로, 그 목록으로 도는 검사는 **방금 추가한 파일을 안 본다** — 저장소 사본을
  전수 스캐너가 *더* 보는 것(위 `.gitignore` 항목)의 **반대 얼굴**이다. 둘 다 "검사 표면이
  의도한 범위와 다르다" 의 사례다.
- **게이트 순서: 테스트가 빌드보다 먼저 돌면서 빌드 산출물을 읽을 수 있다** (sign).
  그러면 첫 실행은 stale 산출물을(또는 없어서) 보고, CI 는 순서를 바꾸면 갑자기 빨개진다.
  산출물을 읽는 검사는 **그 산출물을 만드는 단계 뒤에** 온다는 것을 순서로 못 박는다.
- **실패가 한 축에 몰렸는지 먼저 본다** (pay). *"실패가 mobile 에만 몰렸는가"* — 몰려 있으면
  개별 케이스가 아니라 **그 축의 설정**(뷰포트·로케일·타임존·권한)이 원인일 가능성이 높다.
  개별 실패를 하나씩 고치기 전에 축을 의심하면 N건이 1건이 된다.
- **`svelte-check` 0 errors 인데 화면에 `[object Object]`** (athsra). 타입 검사가 통과해도
  **렌더 결과의 문자열화**는 아무도 안 본다. 객체를 텍스트 슬롯에 넣는 것은 타입상 합법이다.
  → 렌더 산출물에서 `[object Object]` · `undefined` · `NaN` 을 찾는 스윕을 따로 둔다.

## 반대 방향 — **빨강이 거짓일 수 있는 경우** (2026-08-03 athsra 제안, 채택)

여기까지는 전부 *"초록이 왜 거짓인가"* 였다. 반대 축은 비어 있었는데, **형제 세션이
같은 머신에서 동시에 도는 이 환경에서는 그쪽이 더 자주 발생하고 대가가 더 크다** —
오진하면 멀쩡한 코드를 "고치다가" 진짜 회귀를 넣는다.

athsra 실측: 6코어에 **loadavg 250~290**, 그 상태에서 e2e·subprocess 테스트가 무더기로
실패하는데 **실패 대상이 실행마다 바뀐다.**

**4단 진단 — 순서대로. 3단계가 결정적이다.**

| 단계 | 방법 | athsra 실측 |
|---|---|---|
| 1. **격리 재실행** | 그 파일만 단독으로 | 전체 스위트 3 fail → 단독 **23/23 pass**(loadavg 288에서도) |
| 2. **측정 창 확대** | expect timeout 8s → 45s | 그래도 실패 → 부하만으로 설명 안 됨 → 3단계 |
| 3. **baseline 대조** | 내 변경을 `git stash -u` 하고 같은 테스트 | **baseline 에서도 동일 실패** → 내 변경 무관 확정 |
| 4. **CI 를 심판으로** | 통제된 컨테이너(NAS Forgejo) | 두 잡 다 green |

> **1·2단계만으로는 "내가 뭔가 깼나?" 를 못 지운다.** `git stash -u` 로 5분이면 답이
> 나오는데 그전까지는 추론만 반복하게 된다.

**동반 함정 — `quality:all` 은 working tree 를 검사한다.** 백그라운드로 push/게이트를
띄워 놓고 계속 파일을 편집하면 훅이 **반쯤 편집된 트리**를 보고 실패한다. 코드에는
아무 문제가 없다. → 게이트가 도는 동안 트리를 건드리지 않거나, 커밋을 모아 한 번에.

**허브도 같은 밤에 세 번 밟았다**(전부 "빨강이 거짓" 축):

- `quality:all` 이 4회 중 1회 exit 1 → 재현 안 됨. **출력을 `/dev/null` 로 버려 원인
  미상**으로 남았다. 빨간불을 볼 때는 **출력을 남긴 채** 재실행한다.
- 거버넌스가 `test:harness` 안에서만 critical → 단독 실행은 warning. 원인은 **동시에
  돌던 벤치가 저장소 안에 worktree 사본을 만들고 있었던 것**(전수 스캔이 사본을 소스로
  읽었다). 재실행이 아니라 **인과를 찾아야** 갈렸다.
- 로컬 모델 벤치가 시도당 ~300s → 모델이 느린 게 아니라 **VRAM 경합**이었다
  (`/api/ps` 에 다른 프로세스가 6.3GB 보유). 그래서 그 라운드는 이전 라운드와 **비교
  불가**였고, 계측기가 적재 상태를 기록하지 않으면 그 오염이 결과에 남지 않는다.

**한 방향만 보는 대조는 반대편을 침묵으로 덮는다** (athsra 2026-08-04). CI↔로컬 parity 검사가
*"CI 에만 있는 단계"* 만 보고 **«로컬에만 있는 단계»** 는 안 봤다. 반대 방향을 켜자마자
**CI 가 한 번도 안 돌린 로컬 게이트 3개**가 나왔고, 그중 하나는 **전날 실제 버그를 잡은 바로
그 게이트**였다 — 그게 한 머신에서만 살고 있었다. 「census 는 방향을 뒤집으면 유한해진다」와
짝이다: 유한한 쪽을 먼저 만들되, **둘 다** 만들지 않으면 한쪽은 영원히 안 보인다.

**⚠ 그런데 "부하 탓" 으로 끝내면 안 되는 형태가 있다 — 예산 순서** (2026-08-03
atelier-and-folio). 네트워크 의존 테스트가 제목에 *"네트워크 없으면 skip"* 이라 적고
catch → `return` 경로까지 갖췄는데 **그 경로에 한 번도 도달할 수 없었다**:

```ts
// bun 기본 테스트 타임아웃 = 5,000ms
signal: AbortSignal.timeout(8_000)   // ← abort 가 발화하기 전에 테스트가 먼저 죽는다
```

abort 예산이 테스트 예산보다 **길어서** 선언된 graceful skip 이 **죽은 코드**였다.
부하가 낮은 날엔 fetch 가 1초에 끝나 초록, 높은 날에만 빨강 — **"flake 니까 재실행"
으로 넘기기 딱 좋은 형태**이고 실제로 그렇게 분류됐다가, *"제목이 약속한 skip 이 왜
안 걸렸지?"* 를 물어서야 원인이 나왔다.

→ **중첩된 타임아웃은 안쪽이 반드시 더 짧아야 한다.** 그리고 위 4단을 통과해 "부하"
로 분류하기 전에 한 번 더 묻는다: **이 테스트가 선언한 폴백 경로가 실제로 도달
가능한가?** 도달 불가능한 폴백은 빨강을 부하 탓으로 위장한다.

**규칙**: 빨간불에서 결론을 내기 전에 위 4단을 밟는다. 그리고 **재실행으로 넘기지
않는다** — 재현되지 않는 실패는 "없던 일" 이 아니라 **원인 미상**이고, 그렇게 기록한다.

### 새 게이트를 만들 때 (대조쌍 의무 — 결함→실패 · 정상→통과)

**통과하는 것만 확인하면 teeth 가 없는 게이트다.** 반드시 **되돌려서 실패하는지** 본다 —
결함을 일부러 심고 그 게이트가 잡는지. 이 저장소는 이걸 반복해서 배웠다(G31 ④ 의 버전 표류
게이트는 처음에 **아무것도 검사하지 않은 채** 초록이었다 — `Glob` 이 dot-디렉터리를 기본
제외해 `.claude/**` 전체가 비가시였고, 음성 대조가 아니었으면 모르고 넘어갔다).

**그런데 그 한 방향만으로는 계측 오류가 통과한다.** 대상이 통째로 비어 있거나 입력이 안
읽히는 게이트에 결함을 심어도 여전히 "잡힌다" — 결함이 있으면 실패하는 건 맞지만, 정상
입력에서도 실패하고 있기 때문이다. 그래서 **쌍**으로 확인한다:

- 알려진 **결함** 입력 → 게이트가 **실패**해야 한다
- 알려진 **정상** 입력 → 게이트가 **통과**해야 한다

**⚠ 그리고 그 전에: 결함이 «정말 심겼는지»를 먼저 단언한다** (atelier 2026-08-03).
주입에 실패해도 결과는 **똑같이 exit 0** 이라, 그러면 결론이 뒤집힌다 — 멀쩡한 가드를
*"teeth 가 없다"* 로 읽고 뜯어고치게 된다. atelier 실측: 음성 대조 3개 중 2개가 exit 0 이라
가드를 의심했는데, 실제로는 앵커가 **탭 4개 vs 3개**로 안 맞았고(치환 0건) 다른 하나는
`replace(old,new,1)` 이 128행 코드가 아니라 **21행 주석**의 같은 문자열을 바꿨다. 파일이
안 바뀐 것이었고, 앵커를 고치니 전부 exit 1 이 났다.

```sh
python3 -c "
s=open(F).read(); assert ANCHOR in s, '앵커 없음'          # ① 앵커가 실재하는가
assert s.count(ANCHOR)==1, '앵커가 유일하지 않다'           # ② 엉뚱한 데를 바꾸지 않는가
open(F,'w').write(s.replace(ANCHOR, BROKEN, 1))
print('주입 landed:', BROKEN in open(F).read())            # ③ 실제로 바뀌었는가
"
bun run <gate>; echo exit=$?      # ← "landed: True" 를 본 뒤에만 이 값을 읽는다
```

`False` 면 그건 **가드 결과가 아니라 대조 실패**다. 이건 「0건이면 «없다»를 의심하기 전에
probe 가 실물을 재현하는지부터 의심한다」의 **결함 주입** 버전이다 — 대상이 probe 가 아니라
내 조작이다.

⚠ **러너 초록 ≠ 타입 초록.** 같은 제보 #3: `bun test` 는 타입을 안 본다(`brand-tokens.test.ts`
가 8/8 통과인데 `tsc` 는 TS2769). 허브도 이번에 같은 것을 봤다 — MCP 도구 이름을 망가뜨린
상태에서 테스트는 exit 1, `typecheck` 는 **0**. **두 게이트를 따로 읽는다.**

실측 2026-07-29(connect): 신설 CSS 게이트의 첫 실행이 "shortcut 158개 중 0 emit" 을 보고했고,
원인은 대상이 아니라 `--config` 의 기준계 불일치였다(config 경로는 repo 루트 기준인데 cwd 는
앱 디렉터리). 결함을 심는 방향으로는 안 걸린다 — **빈 스타일시트에 결함을 심어도 잡히니까.**
걸린 건 오직 두 번째 방향(문제 힌트를 *제거*했더니 exit 0 이 나오는가)이었다.

**그리고 이 축은 초록에만 있는 게 아니다.** 결과가 비현실적이면 — 0건이든 **100% 위반**이든 —
"대상"보다 **계측**을 먼저 의심한다. 빨강 100% 는 0건과 같은 지문이다. 같은 날 허브도 두 번
밟았다: zsh 가 `$ref:apps/...` 를 파라미터 modifier 로 파싱해 9/9 프로브가 `0B` 를 냈고,
`bun -e` 의 파이프 stdin 읽기가 **모든** 입력에 빈 문자열을 반환했다. 둘 다
`git show … | wc -c` = 51983 이라는 **양성 대조를 세운 뒤에야** 갈렸다.

한 방향만 확인한 게이트는 검출력이 **아직 미측정**이다.

⚠ **«비어 있다» 가 결함인지 판정하려면 그 자리가 무엇인지부터 봐야 한다 — override 층의
부재는 갭이 아니다** (허브 2026-08-04 자기정정). 새 게이트가 *"자기 platform-adapter 에
Connect 소비자로 선언했는데 `ecosystem.json.oauthClients` 에 없다"* 를 **미러 갭 9건**으로
보고했고, 나는 그걸 형제에게 «허브 기록이 빠졌다» 로 통보했다. **틀렸다.**
`oauthClients` 는 인구조사가 아니라 **override 층**이다(`oc.clientId ?? raw.oauthClientId`) —
파생이 이미 맞으면 **항목이 없는 것이 정상**이고, 9건 전부 파생 clientId 가 선언과 같았다.

그리고 «채우는» 행위가 실제로 위험했다: 관례대로 `redirectUris: []` 를 같이 넣었으면
`connect-drift` 의 `if (e.redirectUris.length === 0) continue` 에 걸려 **그 9 repo 가 드리프트
검사에서 통째로 빠진다.** 기록을 보강하려던 행위가 **검사를 끄는 회귀**가 된다.

→ 판정을 **파생 결과와 대조**로 바꿨다(선언 clientId ≠ 파생 clientId 일 때만 «미러 필요»).
대조쌍: 파생을 일부러 어긋내면 `미러 필요 1` 로 정확히 지목, 되돌리면 0.
**교훈: «X 에 항목이 없다» 를 결함으로 부르기 전에 X 가 «필수 목록» 인지 «예외 목록» 인지 본다.**

⚠ **주입을 되돌릴 때 `git checkout <file>` 을 쓰지 않는다** (2026-08-04 허브 실측, 자기보고).
그 파일의 **미커밋 작업까지 같이 지운다.** 이 저장소는 새 프로브를 구현하는 중에 그 프로브
파일에 결함을 심었다가 `git checkout` 으로 복구했고, **방금 쓴 구현 전체가 HEAD 로 되돌아갔다**
(다행히 컨텍스트에 남아 재적용했다). 대조쌍은 «작업 중인 코드» 에 심는 일이 많으므로 이건
드문 사고가 아니다. → **주입 전에 커밋**하거나, 사본(`cp`)을 떠 두고 사본에서 복구한다.
같은 축의 이웃 함정: 형제 세션의 `git add -A` 가 이쪽 WIP 을 자기 커밋에 쓸어 담는다.

#### 세 번째 층 — **가드가 무는 것이 «옳은 것»인가** (2026-08-04 atelier-and-folio)

①(결함에 실패하는가)과 ②(주입이 landed 했는가)를 **둘 다 통과하고도**, 가드가
**자기가 만들어진 이유인 그 사건 위에서 초록**일 수 있다.

atelier 실측. 원 결함: `/api/folio/notifications` 가 `isNotNull(dueAt)` 로 걸렀는데
그 컬럼에 **프로덕션 쓰기가 0건**이었다 — **만들 수 있는 모든 과제가 학생 알림에서
잘려 나갔다.** 만든 가드: *"`isNotNull(<컬럼>)` 로 거르는데 그 컬럼에 쓰는 코드가
없으면 실패."* 대조쌍 **세 방향 전부 통과**했다(결함 심음 → exit 1, 제거 → exit 0,
변형 → exit 0). 거기서 멈췄으면 «가드 완성» 이었다.

그리고 한 질문을 더 했다 — **«이 가드에 어제의 그 사건을 그대로 먹이면?»**
**못 잡았다.** 다른 파일에 `dueAt: dueAtDate` 쓰기가 하나 있어서 *"쓰는 코드가 없다"* 가
거짓이 됐고, 가드는 «쓰기 존재»만 보고 «그 경로가 실제로 도달하는가»는 안 봤다.

**요구**: 새 가드를 만들었으면 **그것을 만들게 한 사건을 그대로 재현해 먹인다.**
합성 결함을 잡는 것과 **원본 사건**을 잡는 것은 다른 명제다 — 합성은 내가 가드를 보고
만들었으므로 통과가 보장돼 있다(「평가셋의 실패 목록을 보고 그 항목을 고치면」의 가드 버전).

판별 질문: *"이 가드가 어제 있었다면 어제의 그 사건을 막았겠는가?"* 답이 «모르겠다» 면
아직 미측정이고, «아니오» 면 가드가 **다른 것을 물고 있다.**

##### ⚠ ③은 둘로 갈린다 — **관측은 같은데 처방이 정반대다** (2026-08-04 athsra)

«심었는데 통과했다» 는 두 가지 다른 원인을 갖는다:

| | 무엇이 틀렸나 | 처방 |
|---|---|---|
| **③-a** | **가드가 무는 것이 옳지 않다** | 가드를 고친다 |
| **③-b** | **결함이 검사 표면 안에 없다** | **가드를 고치면 안 된다** — 대조쌍을 고친다 |

athsra 실측(③-b): E2E 스펙이 단언하는 한국어 문구가 `ko.json` 에 남아 있는지 보는 게이트에
`org_remove` 문구를 심었더니 통과했다. **가드는 정확히 옳게 동작했다** — 몇 분 전에 그 스펙을
`m.org_remove()` 로 바꿔 둬서 그 문구는 **더 이상 리터럴이 아니었다.** 즉 결함을 **검사 대상
밖에** 심은 것이다. 아직 리터럴인 문구로 다시 재니 2건을 잡았다.

**갈라 놓지 않으면 멀쩡한 가드를 넓히다가 오탐을 만든다.** 판별 질문 하나가 가른다:
**"내가 심은 그 결함이, 이 가드가 실제로 들여다보는 대상 안에 있는가."**

##### 그리고 ③은 **새 가드에만 오는 게 아니다** — 매처가 이름보다 좁다 (2026-08-04 atelier)

**가드가 «있다» 는 가드가 «그것을 본다» 가 아니다.** atelier 실측: 「시각 포맷 클래스 가드」가
2026-07-31 부터 **정확히 그 클래스**(런타임 dayPeriod 의존)를 위해 존재했고 *"검사 표면이
비어 있지 않다"* 단언까지 갖추고 있었다. 그런데 매처가 한 글자 좁았다:

```js
/toLocale(?:Time)?String\(/         ← 그때. Date 가 없다
/toLocale(?:Date|Time)?String\(/    ← 고친 것
```

`toLocaleDateString` 에 `hour`/`minute` 를 넣는 건 **정상 동작하는 JS** 다 — 메서드 이름이
아니라 **옵션**이 출력을 정한다. 그래서 결함이 사는 내내 가드는 초록이었다
(측정: 옛 정규식 + 원 사건 → exit 0 · 새 정규식 + 원 사건 → exit 1 · 새 정규식 + 정상 → exit 0).

→ **이미 있는 가드도 원 사건으로 다시 재야 한다.** 「그 클래스를 위해 만들었다」는 기록이
「그 클래스를 덮는다」를 보장하지 않는다. 특히 **매처가 클래스 이름보다 좁은지**를 본다.

###### 그래서 대조쌍의 결함 입력은 **합성하지 않는다** (2026-08-04 atelier, 처방)

위 사례가 ①②③ 어디에도 안 걸린 이유가 처방을 정한다. ①은 통과한다 — **가드의 패턴을 읽고
결함을 만들면 `toLocaleTimeString` 을 만들게 되고 그건 잡힌다.** ②도 통과한다(실제로 심겼다).
③도 아니다 — 가드가 무는 대상은 **옳다.** 좁을 뿐이다.

> **합성 결함을 만들 때 우리는 가드의 패턴을 먼저 읽는다. 그래서 패턴의 좁음이 대조쌍에
> 그대로 복제된다.** 결함이 통과해도 가드는 자기가 틀렸음을 배울 수 없다.

- 결함 입력은 **원 사건 코드를 `git revert`/`git show` 로 되돌려** 쓴다. 원 사건이 있는데
  합성하는 것은 **더 쉬워서**이지 더 정확해서가 아니다.
- 합성이 불가피하면 **가드 소스를 읽지 않은 상태에서** 결함을 쓴다(다른 세션·다른 사람·
  사건 서술만 보고). 패턴을 본 뒤 만든 결함은 그 패턴의 사본이다.
- ⚠ **특히 «범위/대상» 결함은 합성으로 절대 안 잡힌다** (atelier 2026-08-04, 같은 날 세 번째
  실물). 합성자는 게이트의 대상 목록(`SCAN_DIRS`·glob·allowlist)을 **읽고 그 안에 심는다.**
  **원 사건은 대상 밖에 있었기 때문에 사건이 된 것이다.** atelier 실측: TZ 게이트가
  `{pages,components,layouts}` 만 봤고(*"서버는 하이드레이션이 없고 응답은 ISO 로 나가므로
  포맷은 화면 몫"* 이라는 전제), 정작 반례가 서버에 있었다 — `folio-work-projection.ts:29`
  가 카드 **제목**을 완성된 한국어 날짜 문자열로 만들어 응답에 실었다. 범위를 넓히니
  스캔 **93 → 271 파일**. 화면 파일에 합성 결함을 심었으면 **범위 구멍을 영원히 못 본다.**

이 저장소도 같은 밤 같은 것을 밟았다 — `verify:rule-commands` 의 매처가 `bun run` 만 봐서
**`.claude/rules/knowledge.md:11` 이 처방하는 `bunx modfolio-harness-pull` 을 한 번도 본 적이
없었다.** 내 대조쌍은 내가 쓴 정규식을 보고 만들었으므로 영원히 통과했을 것이다.

- ⚠ **그리고 「범위」만이 아니다 — «판정 기준» 결함도 합성으로는 안 잡힌다**
  (atelier 2026-08-05, 위 규칙이 등재된 이유보다 **넓게** 작동한 실증).

  atelier 가 「write-only 표」 게이트를 만들고 음성 대조로 **`anf_leads` 를 읽는 파일 3개를
  지웠는데 게이트가 초록**이었다. 랜딩의 **쓰기**(`api/lead.ts`)가 «소비자» 로 세어졌기
  때문이다. **그런데 결함이 정확히 그 차이였다 — 쓰기는 있었고 읽기가 없었다.**

  > *"내가 «아무 파일이나 하나 지운다» 로 대조를 세웠다면, 참조가 사라지므로 게이트가
  > 물었을 것이고 나는 **teeth 가 있다고 결론지었을 것이다.** 그리고 그 게이트는 실전에서
  > 아무것도 못 잡는다."*

  여기서 대상 집합은 **맞았다**(선언된 표 전체). 틀린 것은 **무엇을 «소비» 로 셀지**였다.
  → **합성 결함은 작성자가 «이미 옳다고 믿는 기준» 에 맞춰 만들어진다.** 그래서 기준
  자체가 틀렸을 때 합성으로는 **원리적으로** 드러나지 않는다. 원 사건은 «대상이 맞는가»
  만이 아니라 **«판정 기준이 맞는가»** 도 시험한다 — 그게 원 사건을 고집하는 두 번째 이유다.

##### 네 번째 형태 — 검사가 **«남의 대상»** 을 봤다 (2026-08-04 athsra)

대상이 비지도(①) 좁지도 가짜(②)도 아니고 **진짜인데 우리 것이 아닌** 경우가 있다.

```
Port 4321 is in use, trying another one...
┃ Local    http://127.0.0.1:4322/            ← 서버는 4322 로 옮겼는데
navigating to "http://127.0.0.1:4321/ai/"    ← 검사는 4321(남의 프로세스)을 봤다
```

하네스가 **요청한 포트를 그대로 믿었다.** 결과는 양방향으로 거짓이다 — 남의 앱이 건강하면
우리 결함이 초록으로 지나가고, 남의 앱이 아프면 우리가 멀쩡한데 빨개진다.
→ 검사 대상의 **실제 주소를 프로세스 출력에서 받아 쓴다.** 요청한 값이 아니라 **배정된 값**이다.
(이 워크스테이션은 형제 세션이 상시 여러 개 도는 곳이라 특히 해당한다.)

⚠ **배포되는 검사기는 이 형태를 «설치되는 순간» 갖는다** (허브 2026-08-04). 위가 포트라면
이건 **디렉터리**다 — 감사 게이트가 루트를 **스크립트 위치 기준**으로 잡고 있었다:

```ts
const ROOT = join(dirname(fileURLToPath(import.meta.url)), '..');
```

허브에서는 맞는다. 그런데 이 파일은 tarball 로 실려 멤버의
`node_modules/@modfolio/harness/scripts/` 로 간다 — 거기서는 **하네스 패키지 자신을 감사**하고,
멤버는 자기 트리가 검사된 줄 안다. 배선 직전에 잡았고, 안 잡았으면 **30 repo 에 거짓 초록을
배포**할 뻔했다. → 배포되는 검사기의 대상은 **호출한 프로젝트(cwd)** 에서 찾고, 그 결과가
`node_modules` 안이면 **판정 불능(2)** 으로 흘린다. 그리고 대조쌍은 **멤버 레이아웃을
저장소 밖에 재현해서** 돌린다 — 허브에서만 돌리면 이 결함은 원리적으로 안 보인다.

### 게이트가 **선언한 전제**가 충족되는지는 결과로 검증되지 않는다 (2026-08-04 athsra)

게이트가 자기 유효성의 조건을 **코드로 선언**하고 주석에 **왜 필요한지까지** 적어 두는데,
그 선언이 **실제로는 안 걸리는** 경우가 있다. 대상도 맞고 검사도 돌고 결과도 진짜다 —
**그 결과가 유효하려면 필요했던 조건이 없었다.**

athsra 실측: axe 스펙이 `test.use({ reducedMotion: 'reduce' })` 로 세워져 있었고 이유도
정확했다(*"진입 애니메이션이 `opacity:0` 으로 시작하면 axe 가 «숨은 요소» 로 건너뛰어
위반이 조용히 누락된다"*). 페이지 안에서 재니:

```
matchMedia('(prefers-reduced-motion: reduce)').matches       → false
document.getAnimations().filter(a => a.playState==='running') → 6
```

| 어떻게 세우나 (Playwright 1.62.1 chromium) | 결과 |
|---|---|
| 프로젝트 `use.reducedMotion` · 최상위 `use` · `test.use` | **false** |
| `page.emulateMedia({ reducedMotion })` · `browser.newContext({ … })` | **true** |
| **`use: { contextOptions: { reducedMotion: 'reduce' } }`** (중첩) | **true** ★ |

⚠ **같은 `use` 블록의 `viewport`·`colorScheme` 은 정상 적용된다** — «`use` 가 통째로
무시된다» 가 아니라 **이 옵션만** 안 간다.

### ★ 근본 원인 — **문서화된 형태가 조용히 버려진다** (athsra 2026-08-04, 저장소 밖 최소 재현)

평평한(문서화된) `reducedMotion` 은 컨텍스트에 도달하지 않고, **중첩된 `contextOptions`**
는 도달한다. 같은 `use()` 호출 안에서 갈린다:

```ts
base.use({ colorScheme: 'dark', reducedMotion: 'reduce' });
// → prefers-color-scheme: dark    = true    ← 배선은 살아 있다
// → prefers-reduced-motion:reduce = false   ← 이것만 안 간다
```

**«설정 실수» 가 아니라는 증거가 이 한 줄이다** — 같은 객체의 다른 키가 가는데 이 키만
안 간다. athsra 는 파생 픽스처를 먼저 의심했다가 base test 에서도 false 인 것을 보고
빈 프로젝트에 최소 재현을 세워 갈랐다(`@playwright/test` 1.62.1 · chromium · WSL2).

→ **처방**: `use: { contextOptions: { reducedMotion: 'reduce' } }` 또는
`page.emulateMedia(...)`. 그리고 **어느 쪽을 쓰든 전제 자체를 단언한다** — 이 버그가
고쳐지면 평평한 형태가 다시 동작할 텐데, 그때 단언이 없으면 **바뀐 줄도 모른다.**

**★ 왜 오래 사나 — 침묵이 두 원인을 구분해 주지 않는다.** 같은 파일의 `bypassCSP` 는 안
걸리면 **axe 주입이 막혀 테스트가 죽는다** — 결과가 원인을 증명한다. `reducedMotion` 은
반대다: 걸려도 «위반 0», 안 걸려도 «위반 0»(애니메이션 중 요소를 건너뛰어서). **두 0 이
구분되지 않는다.**

→ **전제는 그 자체를 단언한다.** 페이지 안에서 `matchMedia(...).matches` 를 읽거나 실행
중 애니메이션 수를 세는 식으로, **결과가 아니라 조건을 잰다.** 그리고 원인을 못 찾았으면
**실행으로 세우고**(`page.emulateMedia`) 선언은 지우지 말고 문서로 남긴다 — 다음 사람이
«없네» 하고 다시 넣다가 같은 것을 밟지 않게.

### 게이트를 검증할 때는 **실행 형태**까지 재현하라 (2026-07-29 modfolio-infra 제안, 채택)

대조쌍을 세워도 **손으로 돌린 형태**와 **CI 가 실제로 쓰는 형태**가 다르면 그 검증은 다른
프로그램을 검증한 것이다. 실측(infra): `gates:handoff` 첫 실행이 `restore` 만 exit 1 인데
**로그는 세 검사 전부 ✓** 였다. `cat file | pg_restore --list` 에서 pg_restore 가 TOC 만 읽고
먼저 끝나면 `cat` 이 EPIPE 로 죽고 그 예외가 종료코드를 오염시킨다 — **통과한 뒤 실패를
보고**하는 구조다. 그리고 이 결함은 **터미널에서 직접 돌리면 안 보인다**(stdout 이 터미널이라
EPIPE 가 안 난다). 리다이렉트·파이프 환경에서만 드러난다.

> **거짓 음성은 노이즈보다 나쁘다 — 게이트를 무시하도록 사람을 훈련시키기 때문이다.**

→ 새 게이트는 **CI/무인 실행과 같은 형태**로 한 번 돌린다: 출력 리다이렉트(`>> log 2>&1`) ·
파이프 · 비대화형 셸 · cron/헤드리스. 형태를 바꾸면 결과가 바뀌는 검사가 실재한다.

#### ⚠ 그리고 거짓 빨강의 대가는 «무시하도록 훈련» 만이 아니다 — **수습 행위가 진짜 결함을 만든다** (허브 2026-08-05 실측, 자기보고)

위 문장은 거짓 음성의 비용을 **주의력**으로 봤다. 이번에 그보다 큰 비용이 나왔다:
**오판정을 «수습» 하는 행위가 멀쩡하던 것을 실제로 깨뜨렸다.**

경위 — 게시 후 레지스트리 실물을 확인하는 검증을 새로 넣었다(옳은 방향이다). 그런데
**즉시 1회만** 읽게 만들었다. canonical(Forgejo)은 게시 직후 packument 에 버전을 바로
싣지 않는다 — 실측 **약 80초**(20초 간격 5회째에 등재+무결). 그래서:

```
[4/5] npm publish → canonical      npm exit 0     ← 실제로는 성공
      failed: exit 0 인데 3.53.0 이 없습니다      ← 검증이 80초를 안 기다렸다
  ↓ 「게시가 실패했구나」
수동으로 npm pack + publish 재시도  → 409 Conflict
  ↓
결과: 그 버전의 **타르볼이 기록된 sha512 와 불일치**
      packument 에는 있고 `latest` 인데 `bun add` → Integrity check failed
      (3.51.0 · 3.52.0 은 일치 — 그 한 버전만)
```

**그 릴리즈는 검증이 없었으면 정상이었다.** 검증이 만든 오판정이 재게시를 부르고,
재게시가 아티팩트를 깨뜨렸다. 그리고 `latest` 가 그리로 옮겨가 있었으므로 **fleet 전체의
`bun add` 가 깨질 수 있는 상태**였다(즉시 이전 버전으로 되돌려 막았다).

→ **처방 셋**:
1. **전파 지연과 «없음» 은 다른 사실이다.** 원격 상태를 게시·배포 **직후** 확인하는 검사는
   **창을 준다**(폴링). 이건 「판정 불능을 통과로 환원하지 않는다」의 시간 축이다.
2. **같은 세션에서 배운 것을 옆 파일에 적용한다.** 이 저장소는 **몇 시간 전에**
   `published-canary` 에서 정확히 같은 전파 지연을 만나 창을 줘서 고쳤다. 그 교훈을
   **새로 쓰는 검증에 옮기지 않았다.** 교훈은 파일마다 다시 배우지 않는다.
3. **빨간불에 대한 «수습» 도 되돌릴 수 없는 행위면 게이트를 통과해야 한다.** 게시된
   아티팩트에 다시 쓰는 것은 비가역이다 — 재게시 전에 *"정말 실패했는가"* 를
   **독립 경로로** 확인한다(여기서는 packument 를 몇 분 뒤에 다시 읽는 것이면 충분했다).

> 이 저장소가 오래 다듬어 온 축은 «초록을 의심하라» 였다. 이번 건은 그 대칭이 **더 비싸게**
> 나타난 경우다 — **빨강을 의심하지 않아서 멀쩡한 것을 고치다가 깨뜨렸다.**

##### 그리고 그 사고의 **하류 원인** — 「거부했다」를 「아무 일도 없었다」로 읽었다 (2026-08-05, 소스 확인)

재게시가 왜 아티팩트를 손상시켰는지 소스에서 갈렸다(`modfolio-infra registry/proxy`):

```
publish.ts:192  await putTarball(...)     ← ① 타르볼을 무조건 덮어쓴다
publish.ts:205  return mergeVersion(...)  ← ② 여기서 no-clobber 409
```

**no-clobber 는 정상 동작했다.** 409 도 정확히 나왔다. 문제는 그 거부가 **①을 되돌리지
못한다**는 것이다 — packument 는 최초 게시본의 integrity 를 유지하고 R2 는 재게시본의
바이트를 갖는다. 소비자에게는 `IntegrityCheckFailed` 로 나타난다.

전제는 주석에 **적혀 있었다**: *"tarball 은 멱등 overwrite 안전"*. 그 문장은
**«같은 버전이면 같은 바이트»** 를 가정하는데 **`npm pack` 은 바이트 재현이 안 된다**
(gzip mtime/OS 비트). 가정이 깨지는 순간 «멱등» 이 «파괴적» 이 된다.

⚠ **그리고 그것을 지킨다는 테스트가 있었다**:
`test/stage3.test.ts` — *"같은 버전 재publish → 409 no-clobber(**immutable**)"*.
**409 가 나오는지만 단언한다.** 그 시점에 타르볼이 이미 바뀌었는지는 안 본다.
「세 번째 부류」(검사를 만족시키는 가장 싼 방법)의 변종인데, 여기서는 **이름이 보장하는
성질(immutable)과 단언하는 것(상태 코드)이 다르다.**

→ **거부·롤백·취소를 단언하는 테스트는 «거부됐는가» 가 아니라 «아무것도 안 바뀌었는가» 를
단언한다.** 그리고 그 음성 대조는 **바이트가 다른 두 입력**이어야 한다 — 같은 바이트로
재시도하면 결함이 있는 코드도 통과한다(그게 이 결함이 오래 숨어 있던 이유다).

##### ⚠ 그리고 **«반증» 도 실물로 해야 한다 — 추론으로 한 안심이 더 나빴다** (허브 2026-08-05, 형제가 반증)

같은 사고의 후속. 손상본을 fleet 에 방송할지 정하려고 「경보 전 반증 1스텝」을 밟았고,
**«노출 0» 이라고 저널에 적었다.** 근거 셋: `dist-tags.latest` 를 되돌렸다 ·
`origin/main` 의 tip 이 그 버전이었던 적 없다 · 창이 15분이고 실패가 시끄럽다.

**30분 뒤 형제가 실제로 막혔다.** 빼먹은 사실 하나:

> **`^3.x` 는 `dist-tags` 를 보지 않는다 — 최고값을 고른다.**
> `latest` 를 되돌려도 범위를 가진 멤버는 여전히 손상본을 해석한다.

그리고 **내 카나리아가 통과한 이유가 정확히 그것**이다 — 카나리아는 범위 없이
`bun add` 하므로 `latest` 를 따라간다. **멤버는 범위를 갖고 있다.** 즉 내 검사는
«소비자가 받는 것» 을 잰다고 선언했지만 **소비자와 다른 방식으로** 물었다.

→ **처방**: 「경보 전 반증」의 반증도 **실물 측정**이어야 한다. 세 값을 재고 네 번째를
**유도**하면 그건 반증이 아니라 추론이다. 여기서 실물은 «멤버 `package.json` 의 범위로
콜드 설치» 한 줄이었다(실측 후 3.53.1 로 해소 확인: `^3.50.0` → 3.53.1 설치 성공).

⚠ **경보를 안 보낸 것보다 «괜찮다» 를 문서에 적은 것이 나빴다.** 침묵은 나중에 고쳐지지만
**기록된 틀린 안심은 다음 사람의 조사를 멈춘다**(「한계 기록이 다음 진짜 0건도 설명해
버린다」와 같은 뿌리).

#### **형태**만이 아니라 **환경 상수**도 갈린다 — `TZ` (2026-08-04 atelier, fleet 실측)

가장 조용한 축은 로케일·시간대다. `toLocaleDateString("ko-KR")` 에 `timeZone` 을 안 주면
**호스트 TZ** 를 쓴다:

```
같은 순간, timeZone 없이
  로컬 개발(KST) → 2026년 10월 15일 00:00
  Cloudflare Workers (UTC) → 2026년 10월 14일 15:00   ← 하루가 밀린다
```

24시간 중 **9시간**이 어긋나고, **개발 박스가 `Asia/Seoul` 이라 로컬에서는 영원히 안 보인다.**
게이트·e2e 의 초록이 «없다» 가 아니라 **«안 봤다»** 인 전형이다. 그리고 SSR·메일·PDF·CSV 처럼
**서버 전용 경로는 하이드레이션 경고조차 안 난다** — 조용히 틀린 값이 고객에게 나간다
(atelier 실측: pay 의 구독 갱신 안내 메일, 영수증 CSV).

허브 fleet 실측 2026-08-04(읽기 전용 정적 스캔, `toLocale(Date|Time)String(` 만):

```
modfolio-connect 22 · gistcore 18 · naviaca 19 · modfolio-press 18 · dle-desk 15
atelier 14 · pdgd 7 · modfolio-pay 5 · modfolio-admin 5 · umbracast 5 …
```

⚠ **첫 스캔은 틀렸다.** `toLocale(Date|Time)?String\(` 로 재서 **숫자 천단위
`toLocaleString()` 까지 세었고**, 그 결과 이 저장소가 «17건» 으로 나왔다. 실제로는 **0건**
(전부 토큰 수 포맷). 위 「매처가 이름보다 좁다」의 **거울상** — 매처가 이름보다 **넓으면**
남의 결함을 우리 것으로 만든다. 옵션 구조로 걸러야 오탐이 0이 된다.

→ 재현 환경은 **형태 + 환경 상수**다: `TZ` · `LANG`/`LC_ALL` · `Intl` 데이터 유무.
프로덕션이 UTC 면 게이트도 `TZ=UTC` 로 한 번 돌린다.

##### ⚠ «서버냐 브라우저냐» 를 가르려 하지 마라 — **갈라도 답이 같다** (atelier 2026-08-04)

이 축의 게이트를 만들면 곧바로 *"이 코드가 서버에서 도는가 브라우저에서 도는가"* 를 묻게
된다. 정적 스캔으로는 (`+server.ts` 같은 파일명 규약을 빼면) **원리적으로 알 수 없다.**
그런데 **알 필요가 없다** — 세 경우 전부 틀리기 때문이다:

| 실행 위치 | 시간대를 런타임에 맡기면 |
|---|---|
| 서버 (Workers = UTC) | 값이 **그냥 틀리다**. 경고 없음 |
| 브라우저 (KST) | 값은 맞지만 SSR 과 갈려 **하이드레이션 불일치** |
| 빌드 시 (Astro prerender 등) | **빌드 머신 TZ 가 굳는다** |

→ 규칙은 「어디서 도는지 알아내라」가 아니라 **«런타임이 시간대를 고르게 두지 않는다»** 다.
게이트 범위에서 서버 코드를 면제하지 않는다 — atelier 가 정확히 그 면제를 했다가
자기 반례를 놓쳤다(위 §범위 결함).

**보는 사람의 시간대가 정말 필요한 앱**(글로벌 SaaS 활동 로그 등)도 규칙은 같다:
시간대 선택이 **명시적**이어야 한다 — `timeZone: <고정값>` 이거나 「viewer-local 이다」라고
이름 붙은 헬퍼이거나. **암묵은 없다.** 암묵이 곧 «런타임이 골랐다» 이고, 그건 서버·브라우저·
빌드에서 각각 다른 답을 낸다. atelier 는 한 발 더 갔다 — 시간대를 **함수 인자에서 없앴다**
(`STUDIO_TIME_ZONE` 상수). *"빠뜨릴 수 있는 것을 인자로 두지 않는다."*

###### ⚠ 다만 **값을 일괄로 강제하면 절반이 망가진다** (pay 2026-08-04, atelier 와 갈린 판단)

pay 실측: 원시 호출 6건은 표면이었고 뿌리는 중앙 포매터였다(`formatDate` **호출부 95건 /
38파일**, 다섯 포매터 전부 `timeZone` 없음). 그런데 **KST 일괄 치환은 틀렸다:**

| 무엇 | 정답 | 왜 |
|---|---|---|
| 결제일·갱신일·영수증 | **KST** | 서울의 10/15 00:30 은 그 사람 달력으로 15일 |
| **청구 기간 라벨** | **UTC** | `getBillingPeriodStart` 가 만든 **UTC 월 경계**에서 나온 값. KST 로 표시하면 **8월 청구서가 «7월 31일부터» 로 보인다** |

두 번째 칸은 **이미 맞게 돼 있었다** — 강제했으면 고치는 게 아니라 깨뜨리는 것이었다.

→ **규칙은 두 층이다**: ① 런타임이 고르게 두지 않는다(예외 없음) ② **어떤 값이 맞는지는
그 데이터의 의미가 정한다** — 게이트는 **명시를 강제하고 값은 강제하지 않는다.**
pay 의 문구: *"UTC 가 맞는 값이면 `timeZone: \"UTC\"` 를 적는다 — **적는 것 자체가 요건이다.**"*
앱 성격상 하나가 정답인 곳(atelier = 학원 KST)은 상수로 못 박아도 되지만, **데이터가 UTC
경계로 만들어졌으면 그 표시는 UTC 가 맞다.**

⚠ **그러므로 「원시 호출 0개 · 예외 목록 없음」은 일반 규칙이 아니라 특수화다** (atelier
자기 정정 2026-08-04, pay 가 반증한 뒤). *"정답이 하나뿐인 도메인에서 «명시» 를 «한 곳에
모음» 으로 강화한 것"* 이고, **그 조건이 없는 앱이 복사하면 값을 틀리게 강제한다.**
일반형은 어디까지나 **«명시를 강제하라»** 다.

⚠ 프로브 함정(pay): `timeZone` 유무를 **여는 줄만 보면** 옵션 객체가 여러 줄일 때
**있어도 «없다» 로 읽는다.** 괄호 균형으로 호출 전체를 잘라 판정하고, **음성 대조에 그
여러 줄 형태를 일부러 심어** 확인한다.

#### **관찰 창이 사건보다 먼저 닫히면** 침묵이 «결함 없음» 이 된다 (2026-08-04 atelier)

수집기를 붙였는데 초록인 것은, 수집기가 **언제까지 보고 있었는지**를 확인하기 전까지
결과가 아니다. atelier 실측: a11y 스펙 50여 라우트에 `pageerror`/`console` 수집기가
**하나도** 없어서 배선했더니 첫 실행에 3건이 나왔다(그중 하나는 **핸들러가 없어 404 인 GET**
을 호출부가 `catch {}` 로 삼키고 화면은 «데이터 없음» 으로 렌더 — 기능이 통째로 죽은 채
게이트는 초록이었다).

⚠ **그런데 처음 배선했을 때도 초록이었고 그게 틀린 초록이었다.** 일부러 심은
`console.error` 가 안 잡혔다 — `waitUntil: "domcontentloaded"` 가 **하이드레이션 전에**
반환한다. 음성 대조가 아니었으면 「런타임 결함 게이트 신설 완료」로 끝났을 자리다.

→ 새 수집기·리스너·구독은 **관찰 창이 사건을 포함하는지**를 먼저 단언한다
(`waitUntil` · 타임아웃 · 언마운트 · 프로세스 종료 시점). 이건 위 「예산 순서」(중첩된
타임아웃은 안쪽이 더 짧아야)의 **관찰 쪽 얼굴**이다.

##### 부분 이관은 «고쳤다» 가 아니라 «고친 자리만 고쳤다» 다

atelier 가 같은 노트에서 세운 규율이고 실측이 뒷받침한다 — 2026-07-31 에 util 을 만들고도
**19곳 중 11곳이 미이관**이었다. 그래서 «`timeZone` 만 있으면 통과» 로 게이트를 만들지
않았다: 통과 형태가 둘로 갈리면(util 을 쓰는 코드 / 손으로 적은 코드) **후자가 다음 사람이
빠뜨리는 자리**가 된다. 원시 호출을 **0개**로 만들고 예외 목록을 두지 않는다 — 필요한
형태는 util 에 함수로 추가한다.

> **이관을 끝내는 것은 게이트이지 의지가 아니다.**

허브 실측이 이걸 그대로 보여준다: gistcore 에는 `lib/util/kst.ts` 가 *"the single source of
truth for the JS-side"* 라고 선언하며 **이미 있는데**, import 하는 프로덕션 파일은 **2개**
(`server/queries/analytics.ts` · `server/usage.ts`)이고 화면 쪽 18곳은 원시 호출이다.
**해결책을 만든 것과 이관이 끝난 것은 다른 사건이다.**

### 판정 순서를 뒤집는 지름길이 문서와 반대로 적혀 있을 수 있다 (2026-07-30 허브 실측)

허브의 `feedback-direction.ts` 는 문서에 *"content beats filename, because the filename is
exactly what went wrong"* 이라고 적어 두고, 정작 코드는 **파일명 검사를 본문 검사보다 먼저**
돌리고 있었다. 그래서 `ecosystem-opinion-20260729-six-**findings**-verification.md`(첫 줄
`# ecosystem → modfolio-connect`, 명백한 허브 회신)가 슬러그 안의 단어 하나로 **member 인바운드**가
됐다. 결과는 **영구히 멈추지 않는 카운터**다 — 허브가 자기 회신에 답할 수는 없으므로 그 1건은
영원히 "미회신" 으로 남는다. 미회신 수는 **무슨 일이 존재하는지를 정하는 숫자**라, 이건 작은
오차가 아니다.

→ 규칙: **주석이 선언한 우선순위를 코드가 지키는지 테스트로 잠근다.** 그리고 카운터가 **줄지
않는 항목**이 있으면 대상이 아니라 분류기를 먼저 의심한다.

### 라이브러리의 "판정 불능" 이 **참**으로 새어 들어올 수 있다 (2026-07-30 허브 실측)

```ts
Bun.semver.satisfies('7.0.2', 'not-a-range')  // → true
```

해독 불가한 range 가 조용히 "만족함" 이 된다 — 판정 불능이 통과로 환원되는 형태인데, 이번엔
**우리 코드가 아니라 라이브러리 안**에 있다. 그래서 우리 쪽 대조쌍만으로는 안 잡힌다.

→ 규칙: 외부 판정 함수에 **신뢰할 수 없는 입력**(레지스트리 문자열·사용자 값·원격 응답)을
그대로 넘기기 전에, **해독 불가를 별도 상태로 먼저 분류**한다. 그리고 그 라이브러리가 쓰레기
입력에 무엇을 돌려주는지 **테스트에 한 줄로 박아 둔다** — 동작이 바뀌면 그 줄이 알려준다.

### 게이트가 프로덕션 러너와 **다르게 파싱하면** 아무도 적용하지 않는 스키마를 축복한다 (2026-07-31 modfolio-connect)

infra 의 "실행 형태까지 재현하라" 와 같은 축인데, 이쪽은 **파서**가 갈린다.

실측: 마이그레이션 러너가 `sql.split(";")` 로 문장을 자르는데, 그건 **`--` 주석 안의 `;`**
에서도 자른다. 게다가 문장별 실패를 abort 대신 `errors[]` 로 삼켜서, 결과는 **절반만 적용된
마이그레이션이 "경고 목록"으로 보고되는** 상태다. 그런데 검증 게이트가 그와 **다른 파서**로
같은 파일을 읽으면, 게이트는 *프로덕션이 실제로 적용할 스키마가 아닌 것*을 축복한다.

→ 규칙: 스키마·설정·마이그레이션을 검증하는 게이트는 **프로덕션 러너와 같은 파서**를 쓰거나,
같은 입력에 대해 두 파서의 산출이 동일한지를 테스트로 잠근다. 그리고 **문장별 실패를 모아
경고로 내리는 러너는 부분 적용을 성공으로 보고한다** — 그 자체가 결함이다.

### "서명이 맞다" 는 "우리가 발급했다" 이지 "**이 용도로** 발급했다" 가 아니다 (2026-07-31 modfolio-connect)

같은 키로 서명한 토큰이 두 종류 이상이면 **서명 검증만으로는 구분이 불가능**하다. Connect 는
ID-JAG 표명과 일반 액세스 토큰을 같은 키로 서명하는데, `typ` 를 안 봤다면 **그 서버가 발급한
아무 액세스 토큰이나** jwt-bearer 로 제시해 다른 앱용 토큰으로 교환할 수 있었다.

→ 규칙: 토큰을 받아들이는 쪽은 서명·`iss`·`aud` 에 더해 **`typ`(또는 등가의 용도 클레임)**
을 검사한다. 자체 AS 를 돌리는 repo 에 특히 해당한다. 이건 암호학 문제가 아니라 **범위**
문제다 — 같은 열쇠가 여는 문이 둘인데 문패를 안 본 것이다.
