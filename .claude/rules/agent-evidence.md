# Agent Evidence — 주장 전 증거 확보 규칙

Agent가 사실을 주장할 때는 반드시 **명령 실행 결과**를 근거로 삼는다. 읽지 않고, grep 하지 않고 단정하지 않는다.

> **이 파일은 규범만 담는다. 증거는 옆에 있다.**
> 2026-08-23 실측: 이 규칙이 **3,068 → 137,065 bytes (6주 44배)** 로 자라 있었고,
> `UNIVERSAL_RULES` 라 **30+ repo 에 매 턴 주입**되고 있었다. 내용은 전부 진짜였다 —
> 틀린 것은 **운반 방식**이었다. 실측 사례는 요약하면 죽으므로 **원문 그대로** 옮겼다:
>
> | 증례 | 무엇 |
> |---|---|
> | `knowledge/canon/evidence-cases-green.md` | 초록불이 거짓인 다섯 부류 |
> | `knowledge/canon/evidence-cases-red.md` | 빨강이 거짓 · 성공 문구인데 안 일어남 · 감시자 |
> | `knowledge/canon/evidence-cases-gates.md` | 대조쌍 3층 · 게이트 전제 · 실행 형태 · TZ |
> | `knowledge/canon/evidence-cases-authority.md` | 권한 선언·실제·감사 |
>
> 아래 각 줄은 그 증례들의 **결론**이다. 근거가 필요하면 해당 파일을 연다.
> ⚠ **이 파일에 사례를 다시 append 하지 않는다** — `context:budget` 게이트가 막는다.
> 새 교훈은 ① 게이트로 만들 수 있으면 게이트 ② 판단 휴리스틱이면 `/debrief` → Muse
> ③ 둘 다 아니면 증례 파일. **규범이 바뀔 때만** 이 파일을 고친다.

## 금지

- "X는 없음" / "0개 감지" / "구현 안 됨" 같은 절대 진술을 근거 없이 쓰지 않는다
- "아마 ~일 것" / "~로 추정" 같은 모호한 주장으로 결론을 대체하지 않는다
- 코드 경로·파일 존재 여부·함수 시그니처를 **기억으로** 말하지 않는다

## 요구

- **존재 여부**: `Glob` 또는 `ls` 결과를 인용
- **사용 위치**: `Grep` 명령 + 히트한 파일·라인 인용
- **행동 흔적**: `git log` / `git diff` 경로 제시
- **수치 주장**: 실행 명령 + 결과 수치 그대로 옮김 (예: `rg -n "pattern" | wc -l` → "N hits")

## 결과 부재일 때

- "확인되지 않았다 (명령 + 조건)" 톤을 기본으로 쓴다
- "없다"는 결론은 **negative 검증 시도 + 그 범위 명시** 이후에만 내린다
- 정보가 확실하지 않으면 사용자에게 질문하거나 조사 범위를 추가 노출한다

## 변경·상태 주장 (diff 읽기) — 오독 방지 (MUST)

- **구조화 파일(JSON/YAML/lockfile)의 diff 는 line-diff 로 단정하지 않는다.** 포매터가 키
  순서만 바꿔도 대량 `-/+` 로 보인다. `bun run json-diff <file> [ref]` 로 **key-level** 비교.
- **에이전트-관리 파일**(`settings.json`·`.mcp.json`·`biome.json`·lock·`memory/*`·CLAUDE.md
  sync 구간)의 세션 중 diff 는 **예상된 자동 churn** — 외부/침해/회귀로 단정하기 전 이번
  세션 에이전트 행위의 부산물인지 대조 (카탈로그 = canon `managed-artifacts.md`).
- **사용자 경보(⚠) 전 반증 1스텝** — "제거됨/유실/외부 변경/보안 이상"은 disconfirming 체크를
  통과한 뒤에만, **근거 명령 결과를 인용해서** 발화한다.
  ⚠ **그 반증도 실물이어야 한다.** 세 값을 재고 네 번째를 유도하면 반증이 아니라 추론이다 —
  기록된 틀린 안심은 침묵보다 나쁘다(다음 사람의 조사를 멈춘다).

# 초록불 — **무엇이 통과했나가 아니라 무엇을 실제로 검사했나** (MUST)

게이트가 초록이라는 것은 **"검사가 통과했다"** 는 뜻이지 **"그것이 검사됐다"** 는 뜻이 아니다.

**다섯 부류** — 2026-07~08 에 서로 조율하지 않은 다섯 repo 가 각자 발견했다. 우연이 아니라 구조다.

| 부류 | 무엇이 틀렸나 | 지문 |
|---|---|---|
| ① 대상 | 비었거나 좁거나 가짜 | 스캔 0건을 통과로 읽음 |
| ② 정답 | 대상도 검사도 진짜인데 **기준이 결함** | 에러 화면을 베이스라인으로 굳힘 |
| ③ 통과 조건 | 만족시키는 **가장 싼 방법**이 의도한 작업이 아님 | import 만 붙이면 초록 |
| ④ 불변식 | **뒤집어도 아무것도 안 깨진다** | 법적·계약적 성질만 바뀜 |
| ⑤ 표면 | 검사 표면이 **배포 대상을 포함하지 않음** | 프로덕션 스키마가 저장소 밖 |

**판별 질문 셋** — 이 세 개가 대부분을 잡는다.

1. ***"이 조건을 만족시키는 가장 싼 방법이 무엇인가?"*** 의도한 작업이 아니면 렌더/런타임 짝을 붙인다
2. ***"이걸 잘못 설정하면 무엇이 실패하는가?"*** 답이 **«아무것도»** 면 거기가 테스트가 필요한 자리다
3. ***"정답(베이스라인·스펙·픽스처)이 어디서 왔는가?"*** 산출물에서 역산했으면 **결함이 명세가 된다**

## A. 판정 자체

- **게이트 결과는 exit code 로 판정한다.** 출력 문자열(`N pass`·`no errors`)은 결과가 아니다.
  ⚠ **판정할 명령이 복합문의 마지막이 아니면 종료코드는 남의 것이다** — 파이프만이 아니라
  `;` · `tee` · `|| true` · `&& echo ok` 가 전부 같은 축이다. `PIPESTATUS`/`pipefail` 을 읽어라.
- **문자열 판정에 파이프를 쓰지 않는다.** `set -o pipefail` 아래 `grep -q` 는 첫 매치에서
  즉시 끝나 왼쪽을 SIGPIPE(141)로 죽인다 — 검사가 반대로 붙어 있으면 **진짜 결함이 초록이 된다.**
  셸 내장 `case "$OUT" in *"…"*)` 를 쓰거나 `grep -c` 로 **값** 판정.
- ***"이 스크립트가 출력하는 숫자가 exit code 에 들어가는가?"*** — 개수를 세고 출력까지 하면서
  판정에는 안 쓰는 스크립트가 압도적으로 흔하다(감사 7건 중 6건). 수정도 대개 한 줄이다.
- **판정 불능과 위반은 다른 종료 코드여야 한다.** 위반=1 · 사용 오류/대상 0건=2.
  ⚠ 데이터 층에도 내려온다: **«읽지 못했다» 와 «비어 있다» 를 같은 값으로 표현하면**
  `parse → 수정 → serialize → PUT` 한 번에 원본이 소멸한다. 빈 결과일 때 **쓰기를 건너뛴다.**
- **읽기 실패를 판정값으로 환원하지 않는다.** `catch { return false }` 는 "파일 없음"을
  "위반 없음"으로 바꾼다 — 스캔에서 빠진 것이 **의도된 제외처럼** 보고된다.

## B. 검사 대상

- **빈 대상은 통과가 아니라 실패다.** "0건이라 위반이 없다"와 "0건을 대상으로 검사했다"는 다른 문장이다.
  ⚠ **간접 형태가 더 안 보인다** — 게이트가 외부 설정(`testMatch`·`include`)을 읽어 커버리지를
  판정할 때 «못 읽음»을 «없음»으로 접으면 **잣대가 0**이 되어 전부 통과한다. 선언 수와 파싱
  수를 비교해 다르면 **판정 불능(2)**. 그 설정이 하나뿐이라는 **전제 자체도** 검사한다.
- **검사 표면이 의도한 범위를 덮는지 먼저 확인한다.** ⚠ **«매 커밋 검사한다» 는 «저장소를
  검사한다» 가 아니다** — diff 게이트는 이미 들어와 있는 것에 원리적으로 침묵한다. 옆에
  **전수 스윕**을 둔다.
- **범위는 양방향으로 틀린다.** 좁으면 놓치고(`git ls-files` 는 새 파일을 숨긴다), 넓으면
  남의 것을 우리 것으로 만든다(`.gitignore` 는 파일시스템 스캐너를 못 가린다 — 저장소 안에
  저장소 사본을 두지 않는다. 임시 트리는 `tmpdir()` 에).
- **설정이 둘로 나뉘면 어느 쪽에서도 검사되지 않는 파일이 생긴다.** "각 설정이 통과한다"와
  "모든 파일이 어딘가에서 검사된다"는 다른 문장이다 — 파티션이 전체를 정확히 한 번씩 덮는지
  자체를 테스트로 잠근다.
- **검사가 «남의 대상»을 볼 수 있다.** 요청한 포트가 아니라 **배정된** 포트를 프로세스 출력에서
  받아 쓴다(형제 세션 상시 가동). ⚠ **배포되는 검사기는 설치되는 순간 이 형태를 갖는다** —
  루트를 스크립트 위치로 잡으면 멤버에서 **하네스 자신을 감사**한다. 대상은 **cwd** 에서 찾고
  결과가 `node_modules` 안이면 판정 불능.
- **스텁은 프로덕션보다 관대하면 안 된다.** ⚠ 관대함은 «응답»만의 축이 아니다 — 모의 서버는
  «무엇을 돌려주나»로 설계되고 «무엇을 받아들이나»로는 설계되지 않는다. **모르는 경로에 404 를
  내야** 한다. 대조는 **유한한 쪽**(라우트 목록)에서 출발한다.
- **픽스처가 «앱이 실제로 쓰는 상태»를 재현하는가.** props 를 다 채운 것으로 부족하다 —
  slot/children 이 빈 컴포넌트는 위반 0이 나오고, 브라우저가 잘못된 자식을 조용히 삼켜 눈으로도 안 보인다.

## C. 측정 도구가 답을 바꾼다

- **★ `rg` 에 `-r` 을 붙이지 않는다.** `--replace` 다. `-rn` 은 grep 습관으로 «재귀+행번호»처럼
  읽히지만 rg 는 기본 재귀라 그런 플래그가 없다. **exit 0 · 히트 수도 파일명도 맞고 인용문만 틀리다.**
  한 세션에 3회 밟았고 두 번은 형제 repo 로 보낼 오보를 만들었다. 행번호 `-n` · 파일명 `-l` · 개수 `-c`.
- **판단 근거로 쓸 출력을 `head`·`tail`·`grep` 으로 자르지 않는다.** 길면 `> log` 로 남기고 전체를 읽는다.
  ⚠ **자르는 것이 내가 아닐 수 있다 — 서버가 자른다.** 200 이고 JSON 이 온전하고 «더 있음»이
  어디에도 없다. **받은 개수가 기본 한계와 정확히 같으면 판정 불능**으로 흘린다.
- **표시용으로 자른 문자열이 판정 입력이 되면 멀쩡한 것이 «부재»로 보고된다.** 실행 헬퍼는
  **판정용 전문과 표시용 축약을 분리해** 반환한다.
- **`rg`/`grep` 에 항상 경로 인자를 준다.** 없고 stdin 이 파이프면 **파일시스템 대신 stdin 을
  뒤진다** — 빈 «0건» 이거나 **스크립트 소스를 검색한 그럴듯한 목록**이 나온다. TTY 면 멈춘다
  (= 손으로 돌리면 재현 안 되고 자동화에서만 난다). 서브프로세스엔 `stdin=DEVNULL`.
- **JSONC 를 정규식으로 주석 제거하지 않는다** — `"https://…"` 가 잘려 파싱 실패 → 빈 값 →
  «설정에 없다»로 오독. wrangler·tsconfig·biome 이 전부 JSONC 다.
- ***"내 확인 요청과 소비자의 요청이 바이트 단위로 같은가?"*** — 같은 URL 이 같은 문서를 뜻하지
  않는다. npm packument 는 `Accept` 로 full/abbreviated 가 갈리고, 웹 라우팅도 `Accept: text/html`
  에만 301 한다. **브라우저·소비자가 보내는 헤더 그대로** 물어라.
- **집계는 정확한데 «무엇을 세는지»가 다를 수 있다.** 재현해도 같은 수가 나오므로 검산으로는
  안 걸린다. `GROUP BY` 결과로 결론 내기 전에 **그 그룹의 행 몇 개를 펼쳐 본다** — 시계열에서
  «반복»은 대개 **상태 전이의 흔적**이다.
- **정규식 곡예로 «X 가 존재하는가»를 묻지 않는다.** `(?!…)` 를 가변 길이(`\s*`) 뒤에 놓으면
  엔진이 되돌아가 **통과 방향으로** 참을 만든다(`outline: none` 이 «대체 있음»으로 매치).
  구조 단위로 자른 뒤 판정하고, 대조쌍에 **공백 있는 형태와 없는 형태를 둘 다** 넣는다.
- **결과가 0건이면 «없다»를 의심하기 전에 probe 를 의심한다** — 알려진 양성 1건을 잡는지
  먼저 통과시킨다. 통과 못 하면 그 측정은 결과가 아니다. ⚠ **1건이어도 그게 나일 수 있다**
  (`pgrep -f` 가 자기 감시 루프를 잡는다).
- **재현 실패는 신고자의 절차를 그대로 밟은 뒤에만 보고한다.** 못 재현했을 때 가장 먼저
  의심할 것은 버그의 부재가 아니라 **내가 절차를 바꿨는가**다.

## D. 정답이 어디서 왔나

- **산출물·구현·표시문자열에서 명세를 역산하면 결함이 명세가 된다.** 스크린샷 베이스라인은
  **페이지-에러 게이트를 먼저 켜고** 찍는다.
- **평가셋의 실패 목록을 보고 그 항목을 고치면, 오른 수치는 답을 본 시험의 점수다.** 개선안은
  **독립 출처**에서 만들거나 **홀드아웃**을 먼저 뗀다.
- **문서·선언은 필요조건이 아니라 충분조건이어야 한다** — 선언한 조건**만** 만족시킨 최소
  마크업으로 게이트를 돌려라.
- **canon 을 인용하는 도구는 *덜* 집행하는지만이 아니라 *더* 집행하는지도 본다.** 과탐은
  **규약 준수를 벌하므로 채택을 직접 막는다.** 그리고 아무도 안 켜는 opt-in 검사는 틀린 채 오래 산다.
- **발신 경계의 스키마는 생산자보다 엄격하면 안 된다.** 더 좁은 공유 스키마는 계약이 아니라
  희망이고, `safeParse` 실패가 이벤트를 **DROP** 한다. **수신 엄격 · 발신 관대** — 방향이 반대면 안 된다.

## E. 아무도 안 보는 표면

- **코드는 타입이 지키지만, 사람이 읽고 그대로 구현하는 표면은 아무 게이트도 안 본다.**
  공개 문서 · **DB 스키마 주석**(가장 조용하고 가장 정확히 복제된다) · **고객에게 나가는
  이메일 본문**. 발신 목록·헤더명·에러코드를 갖는 문서는 **발신 코드와 양방향 대조**한다.
- **게시된 열거값 중 «아무도 못 내는 것»은 미구현이 아니라 거짓 계약이다.** 하류는 죽은
  분기를 짜고 **아무것도 실패하지 않아** 눈치챌 수 없다. 타입 계약이면 하류가 그것을
  **컴파일러가 보증한 사실**로 받는다 — 셋 중 가장 강하게 믿긴다.
- **«쓰기는 있는데 읽기가 없다»** — 코드에 결함이 없고 제품에 구멍이 있다. 타입·린트·테스트·
  빌드·e2e 가 전부 정상이고 **아무도 게이트를 속이지 않았다.** census 를 유한한 방향으로:
  선언된 표 → 읽기/쓰기를 갈라 세고 **읽기 0이면 위반**. 면제는 **사유 필수**.
- **도달 가능성은 boolean 이 아니라 «어떤 상태에서»다.** 링크가 빈 상태 블록 안에만 있으면
  항목이 1개부터 영구히 사라진다. **«링크가 있는가»가 아니라 «언제 보이는가»**로 묻는다.
  같은 스윕에서 **인바운드 0인 배포된 기능**도 나온다 — 문이 없으면 없는 기능과 구분되지 않는다.
- **테스트가 있다는 사실은 그 코드가 도달 가능하다는 증거가 아니다.** 자기 스펙을 소비자로 세지 않는다.
- **UI 가 단언하는 상태는 읽은 값에서 파생시킨다.** 조건부가 아닌 상태 문자열은 그 자체가 결함 후보다.
- **배포 대상이 저장소 밖에 있다.** 원격 마이그레이션 원장 ↔ 저장소를 **양방향** 대조
  (`원격 ⊄ 로컬`이 더 위험하다). ⚠ `wrangler d1 migrations list --remote` 는 미적용이 있어도
  **exit 0** — 표를 파싱하지 말고 **테이블을 조회**한다. 이 게이트는 `release:gate` 가 아니라
  **배포 명령 앞**에 건다.
- **뒤집어도 아무것도 안 깨지는 불변식은 테스트가 유일한 방어다.** 주석은 실행되지 않는다.

## F. 도구가 원리적으로 못 보는 것

- **못 보는 것은 그 도구의 통과가 «없다»가 아니라 «안 봤다»이다.** 게이트를 깔 때 **무엇을 못
  보는지**를 함께 적고, 못 보는 자리는 다른 검출기로 덮거나 **«미검사»로 명시**한다.
  ⚠ **«이 도구가 X 를 못 본다»는 X 가 있는 상태에서 재야 한다** — 없는 한계를 적으면 그 기록이
  **다음의 진짜 0건도 설명해 버린다.**
- **비치명(warn) 경로일수록 이유가 실제로 보이는지 따로 확인한다.** 치명 경로는 멈추니 눈에 띈다.
- **로컬이 아니라 소비자가 받는 것을 검사한다** — 게시본은 `files` 로 걸러진다(`canary:published`).
- **«이미 대응했다»는 «지금도 대응돼 있다»를 보장하지 않는다.** 대조 상대(advisory DB)가
  **우리 커밋과 무관하게 움직인다.** ⚠ **핀은 바닥을 정하지 천장을 밀지 않는다** — `^3.1.3` 을
  적어 둬도 lock 이 3.1.4 면 영원히 3.1.4 이고, 새 범위가 `<3.1.5` 면 그 핀은 **취약본을 고정하는
  장치**가 된다. 예외·핀 기록에 **«어떤 범위에 대해»**를 적는다. `revisit_after` 는 하한이지 판정이 아니다.
- **인용은 증거가 아니다.** 「X 가 폐지/변경/금지됐다」는 제보는 **1차 출처의 정확한 식별자**를
  대조한 뒤에만 행동한다 — «비슷한 이름»은 근거가 아니다.
  ⚠ **자기가 인용한 문서는 «검사 대상»으로 안 보인다.** 같은 편지에서 네 개를 옳게 대조하고
  다섯 번째만 빠뜨리는 것이 이 부류의 전형이다.
- **«실물 + 인과»가 한 노트에 오면 실물만 받고 인과는 따로 잰다.** 실물이 인과에 신뢰를
  빌려준다. «A 가 되니까 B 는 안 된다»는 **B 를 시도한 적이 있는지** 묻는다 — 대개 없다.

## G. census 는 방향을 뒤집으면 유한해진다

| 방향 | 성질 |
|---|---|
| 생산자 코드 → 계약 | 대상이 **무한**. 리터럴·동적 조립·조건부 발행을 계속 놓친다 |
| **계약 유니온 → 발행 코드** | 대상이 **유한**하고 목록이 이미 있다. **0건이 곧 답이다** |

둘 다 필요하지만 **유한한 쪽을 먼저 만든다.** 그리고 **optional + 기본값은 분류를 강제하지
않고 숨긴다** — ***"이 필드를 optional 로 두면 분류 안 된 것이 몇 개인지 누가 세나?"*** 답이
«아무도»면 **필수·무기본값**이 맞는 자리다. 그러면 컴파일러가 그 축의 전수 목록을 만들어 준다.

# 반대 방향 — 빨강·침묵도 거짓일 수 있다

형제 세션이 상시 도는 이 워크스테이션에서는 이쪽이 더 자주 나고 대가가 크다 —
오진하면 **멀쩡한 코드를 «고치다가» 진짜 회귀를 넣는다.**

## ① 빨강이 거짓 — 4단 진단, 3단계가 결정적

| 단계 | 방법 |
|---|---|
| 1. 격리 재실행 | 그 파일만 단독으로 |
| 2. 측정 창 확대 | 타임아웃을 늘려 부하로 설명되는지 |
| **3. baseline 대조** | **내 변경을 `git stash -u` 하고 같은 테스트** ← 여기서 «내가 깼나»가 지워진다 |
| 4. CI 를 심판으로 | 통제된 컨테이너 |

- **재실행으로 넘기지 않는다.** 재현되지 않는 실패는 «없던 일»이 아니라 **원인 미상**이고 그렇게 기록한다.
- **빨간불은 출력을 남긴 채** 재실행한다. `>/dev/null` 로 버리면 원인을 영영 못 찾는다.
- 게이트가 도는 동안 트리를 편집하지 않는다 — `quality:all` 은 **working tree** 를 본다.
- **중첩된 타임아웃은 안쪽이 반드시 더 짧아야 한다.** abort 예산이 테스트 예산보다 길면
  선언된 graceful skip 이 **죽은 코드**가 되고, 그 빨강이 «flake» 로 분류된다.
- **실패가 한 축에 몰렸는지 먼저 본다**(뷰포트·로케일·타임존·권한). 축을 의심하면 N건이 1건이 된다.
- ⚠ **거짓 빨강의 대가는 «무시하도록 훈련»만이 아니다 — 수습 행위가 진짜 결함을 만든다.**
  실측: 게시 검증이 전파 지연(80초)을 «실패»로 읽어 재게시했고, **타르볼이 sha512 와 불일치**해
  `latest` 가 손상본을 가리켰다. **되돌릴 수 없는 «수습»도 게이트를 통과해야 한다.**

## ② 성공 문구가 있는데 일이 안 일어났다

**지문**: ① 성공 문구가 출력된다 ② **실패 메시지가 없다** ③ 원격/외부 상태만 조용히 안 바뀐다.

실측: git 은 훅보다 **먼저** SSH 를 연다. 훅이 10분을 넘으면 그 연결이 유휴로 끊기고
**git 은 메시지 없이 exit 1**. 훅은 "gate green"을 출력한 뒤였다.

```
GIT_SSH_COMMAND="ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=60 -o TCPKeepAlive=yes"
```

→ **게이트 통과를 «외부에 도달했다»의 증거로 읽지 않는다.** 원격 상태를 따로 본다
(`git ls-remote` · packument · 배포 Version ID). 「commit≠deployed」와 같은 축인데,
여기서는 **훅이 성공을 말해서** 더 강하게 믿긴다.

## ③ 일은 끝났는데 감시자가 모른다

`pgrep -f "패턴"` 은 **그 패턴을 담은 감시 루프 자신**을 잡는다 — 조건이 영원히 참이다.
실측 22시간. → **PID 로 기다린다**(`wait`·`kill -0`). 그리고 **감시 루프에 상한을 둔다** —
무한 `until` 은 정상 종료와 감시 결함을 구분하지 못한다.

## ④ 오탐을 고치다가 검출력을 0으로

오탐 수정의 대조쌍에는 **오탐 케이스와 진짜 위반을 함께** 넣는다. 오탐만 넣으면 «사라졌다»만
보이고 그 수정이 **검출력까지 지웠는지**는 안 보인다.

## ⑤ 계약이 producer 를 선언하는데 아무도 안 쏜다

「소비자가 없다」는 갭은 **생산자 실재로 먼저 가른다**(매니페스트가 아니라 **코드**로):
`live`(진짜 갭) · `contract-ahead`(**갭이 아니다** — 계약이 먼저 오는 것은 설계) · `undecidable`.

# 새 게이트를 만들 때 — 대조쌍 의무

**통과하는 것만 확인하면 teeth 가 없다.** 반드시 쌍으로: 결함 입력 → **실패** · 정상 입력 → **통과**.
한 방향만 확인한 게이트는 검출력이 **아직 미측정**이다.

### ⓪ 결함이 «정말 심겼는지»를 먼저 단언한다

주입에 실패해도 결과는 **똑같이 exit 0** 이라 결론이 뒤집힌다 — 멀쩡한 가드를 «teeth 없음»으로 읽는다.

```sh
python3 -c "
s=open(F).read(); assert ANCHOR in s, '앵커 없음'
assert s.count(ANCHOR)==1, '앵커가 유일하지 않다'
open(F,'w').write(s.replace(ANCHOR, BROKEN, 1))
print('주입 landed:', BROKEN in open(F).read())"
bun run <gate>; echo exit=$?      # ← 'landed: True' 를 본 뒤에만 이 값을 읽는다
```

⚠ 되돌릴 때 **`git checkout <file>` 을 쓰지 않는다** — 그 파일의 미커밋 작업까지 지운다.
주입 전에 커밋하거나 사본(`cp`)에서 복구한다.

### ① 심었는데 통과했다 — **원인이 둘이고 처방이 정반대다**

| | 무엇이 틀렸나 | 처방 |
|---|---|---|
| **a** | 가드가 무는 것이 옳지 않다 | 가드를 고친다 |
| **b** | 결함이 **검사 표면 안에 없다** | **가드를 고치면 안 된다** — 대조쌍을 고친다 |

판별: ***"내가 심은 그 결함이, 이 가드가 실제로 들여다보는 대상 안에 있는가."***
갈라 놓지 않으면 멀쩡한 가드를 넓히다가 오탐을 만든다.

### ② ★ 결함 입력은 **합성하지 않는다** — 원 사건을 `git show` 로 되돌려 쓴다

> **합성 결함을 만들 때 우리는 가드의 패턴을 먼저 읽는다. 그래서 패턴의 좁음이 대조쌍에
> 그대로 복제된다.** 결함이 통과해도 가드는 자기가 틀렸음을 배울 수 없다.

- **«범위/대상» 결함은 합성으로 절대 안 잡힌다** — 합성자는 게이트의 `SCAN_DIRS`·glob 을
  **읽고 그 안에 심는다.** **원 사건은 대상 밖에 있었기 때문에 사건이 된 것이다.**
- **«판정 기준» 결함도 마찬가지다** — 합성 결함은 작성자가 **이미 옳다고 믿는 기준**에 맞춰
  만들어지므로, 기준 자체가 틀렸을 때 원리적으로 드러나지 않는다.
- 합성이 불가피하면 **가드 소스를 읽지 않은 상태에서** 쓴다(다른 세션·사건 서술만 보고).

### ③ 만들었으면 **그것을 만들게 한 사건을 그대로 먹인다**

***"이 가드가 어제 있었다면 어제의 그 사건을 막았겠는가?"*** «모르겠다»면 미측정, «아니오»면
가드가 **다른 것을 물고 있다.** ⚠ **이미 있는 가드도 원 사건으로 다시 재야 한다** — 「그 클래스를
위해 만들었다」는 기록이 「그 클래스를 덮는다」를 보장하지 않는다(매처가 이름보다 좁을 수 있다).
반대로 **넓으면** 남의 결함을 우리 것으로 만든다.

### ④ 게이트가 **선언한 전제**는 결과로 검증되지 않는다

전제가 안 걸려도 «위반 0», 걸려도 «위반 0» — **두 0 이 구분되지 않는다.**
→ **결과가 아니라 조건을 잰다**(페이지 안에서 `matchMedia(...).matches` 를 읽는 식).
실측: Playwright 의 평평한 `use: { reducedMotion }` 은 컨텍스트에 **도달하지 않고**
중첩 `contextOptions` 는 도달한다 — 같은 객체의 `colorScheme` 은 정상 적용된다.

### ⑤ **실행 형태**와 **환경 상수**까지 재현한다

- 손으로 돌린 형태와 CI 가 쓰는 형태가 다르면 **다른 프로그램을 검증한 것**이다 —
  출력 리다이렉트 · 파이프 · 비대화형 셸로 한 번 돌린다(EPIPE 는 터미널에서 안 난다).
- **`TZ`·`LANG`** — `timeZone` 없는 `toLocaleDateString` 은 호스트 TZ 를 쓴다. 개발 박스가
  `Asia/Seoul` 이라 **로컬에서는 영원히 안 보이고** Workers(UTC)에서 하루가 밀린다.
  프로덕션이 UTC 면 게이트도 `TZ=UTC` 로 한 번 돌린다.
  ⚠ 규칙은 «어디서 도는지 알아내라»가 아니라 **«런타임이 시간대를 고르게 두지 않는다»** 다
  (서버·브라우저·빌드 세 경우 전부 틀린다). 다만 **값은 강제하지 않는다** — UTC 월 경계에서
  만든 청구 기간 라벨은 UTC 가 맞다. **적는 것 자체가 요건이다.**

### ⑥ 관찰 창이 사건보다 먼저 닫히면 침묵이 «결함 없음»이 된다

새 수집기·리스너·구독은 **관찰 창이 사건을 포함하는지** 먼저 단언한다
(`waitUntil` · 타임아웃 · 언마운트 · 프로세스 종료 시점).

### ⑦ 부분 이관은 «고쳤다»가 아니라 «고친 자리만 고쳤다»다

통과 형태가 둘로 갈리면(util 을 쓰는 코드 / 손으로 적은 코드) **후자가 다음 사람이 빠뜨리는
자리**가 된다. 원시 호출을 **0개**로 만들고 예외 목록을 두지 않는다.
> **이관을 끝내는 것은 게이트이지 의지가 아니다.**

### ⑧ 한 방향만 보는 대조는 반대편을 침묵으로 덮는다

CI↔로컬 parity 를 «CI 에만 있는 단계»로만 보면 **CI 가 한 번도 안 돌린 로컬 게이트**가 안 보인다.

### ⑨ 러너 초록 ≠ 타입 초록

`bun test` 는 타입을 안 본다. **두 게이트를 따로 읽는다.**

# 권한을 여는 코드는 **선언·실제·감사** 셋이 같은지 본다

권한 결함은 기능처럼 실패하지 않는다 — 넓게 열려도 작업은 성공하므로 아무도 눈치채지 못한다.
실측: `grant <repo>` 한 줄에 **31 repo 가 열렸고**, 감사 로그에는 **실제 권한과 다른 값**이 적혔다.

⚠ **셋 중 감사가 가장 나쁘다** — 「기록이 남았다 ≠ 일어난 일이 기록됐다」.

***"이 권한을 회수한 뒤 상태에 무엇이 남는가?"*** 범위가 남으면 그것은 회수가 아니라 비활성화다.
⚠ 회귀 테스트는 **성질 서술만으로 부족하다** — 「단일 repo 여야 한다」를 배열 리터럴로 단언하면
구현이 다시 누적으로 돌아가도 통과한다. **소스를 직접 읽어** 패턴 부재를 단언한다.

**승인은 «해도 된다»이지 «옳다»가 아니다.** 되돌릴 수 있으면 **재서** 정한다 — ① 적용 **전에**
기준선을 기록 ② 소표본이 «불변»이면 큰 표본으로 다시 재고 갈리면 **큰 쪽** ③ 판정 근거를 **표로** 남긴다.
