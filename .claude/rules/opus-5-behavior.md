# Opus 5 행동 보정 — 하네스 적용 규칙

Opus 5 (2026-07-24 릴리즈) 는 Opus 4.8 과 **행동이 다르다**. 아래는 그 차이가 이 하네스의 agent/skill 프롬프트와 부딪히는 지점만 다룬다. 일반적인 Opus 5 프롬프팅 지침은 Claude Code 자체 시스템 프롬프트가 이미 주입하므로 여기서 반복하지 않는다.

적용 대상: `.claude/agents/*`, `.claude/skills/*`, 그리고 이 repo 에서 프롬프트를 작성하는 모든 지점.

---

## 1. 자기검증 지시를 넣지 않는다 (신규 작성 시)

Opus 5 는 **시키지 않아도 자기 작업을 검증한다.** "최종 검증 단계를 포함하라", "subagent 로 검증하라", "답을 다시 확인하라" 같은 지시를 프롬프트에 넣으면 **과잉검증**이 되어 토큰과 시간만 늘고 품질은 오르지 않는다.

⚠️ **이건 일반적인 프롬프팅 베스트프랙티스를 뒤집는 항목이다** — "self-check 시켜라"는 보통 옳은 조언이지만 이 모델에서는 아니다. 프롬프트 템플릿을 재사용할 때 이 예외를 기억할 것.

### 삭제 대상이 **아닌** 것 (절대 건드리지 말 것)

이 규칙은 **모델에게 스스로를 검증시키는 프롬프트 문구**만 대상으로 한다. 아래는 전부 유지한다 — 혼동하면 우리 증거 규율이 무너진다.

- **결정적 게이트**: `bun run quality:all`, `bun run release:gate`, `bun run check`, 테스트 스위트, lint/typecheck
- **도구 기반 검증**: `mcp__svelte__svelte-autofixer`, 빌드, **배포 Version ID 변화 확인**(⚠ 라이브 200 은 배포 확인이 **아니다** — 배포 실패는 사이트를 안 죽이고 안 바꾼다. canon `cf-deploy.md` v1.4.0 §검증)
- **증거 규율** (`agent-evidence.md`): "주장 전 명령 실행 결과를 인용한다", "subagent 의 green claim 은 증거가 아니다 — 메인이 게이트를 직접 재실행한다". 이건 자기검증이 아니라 **환각 방지**이며 Opus 5 에서도 그대로 필요하다.
- **리뷰의 coverage-first 2단 분리** (§4) — 이건 검증이 아니라 보고 정책이다.

구분 기준 한 줄: **"모델아 네 답을 다시 봐라" = 삭제. "이 명령을 실행하고 결과를 인용해라" = 유지.**

## 2. subagent 위임에 상한을 둔다

Opus 5 는 Opus 4.8 과 **반대 방향**이다 — 4.8 은 위임을 꺼려 "더 위임하라"고 밀어줘야 했지만, **Opus 5 는 과하게 위임한다.** 4.8 용으로 넣은 "적극적으로 subagent 를 소환하라" 류 문구가 남아 있으면 제거한다.

위임은 비용을 곱한다: 각 subagent 가 컨텍스트를 다시 세우고, 다시 탐색하고, 보고하고, 그걸 다시 읽어야 한다.

- **위임할 것**: 진짜로 독립적이고 병렬 가능한 큰 작업 (여러 repo 전수 관측, 넓은 다중 파일 조사)
- **위임하지 말 것**: 직접 몇 번의 도구 호출로 끝나는 일 (파일 몇 개 읽기, 단순 검색, 간단한 수정). **검증 목적의 위임은 특히 금지** — §1 과 같은 뿌리다
- 하나로 되면 하나만 쓴다. 여러 개를 띄울 땐 한 메시지에 담아 동시 실행시킨다
- 위임했으면 그 결과를 신뢰한다 — 다시 하지 않는다 (단, 게이트 재실행은 §1 의 증거 규율이라 예외)

## 3. 요청 범위를 임의로 넓히지 않는다

Opus 5 는 요청하지 않은 인접 작업을 덧붙이는 경향이 있다 (리팩터링 끼워넣기, 안 시킨 추상화, 일어날 수 없는 경우의 에러 처리).

- 요청받은 것을 요청받은 범위로 전달한다. 애매하면 신중한 동료처럼 판단하되, 해석에 따라 결과가 크게 달라지면 묻는다
- 요청이 잘못됐다고 판단되면 **한 문장으로 말하고 요청대로 진행**한다 — 조용히 좁히거나 넓히거나 바꾸지 않는다
- 작업 전체를 끝낸다. 못 끝낸 부분이 있으면 나머지를 다 하고 **무엇이 왜 빠졌는지 명시**한다
- 버그 수정에 주변 정리를 끼워넣지 않는다. 일회성 작업에 헬퍼를 만들지 않는다

## 4. 리뷰는 coverage-first 를 유지한다 (변경 없음)

severity 필터를 문자 그대로 따라 실측 recall 이 떨어지는 현상은 **Opus 5 에서도 동일**하다. "확실한 것만 / 중요한 것만 / 사소한 건 빼고" 류 지시는 여전히 발견 누락을 만든다.

→ **발견 단계 = 전수 보고**(확신도·심각도 태그 부착), 필터·랭킹은 하위 triage 단계로 분리. 기존 2단 분리 패턴을 그대로 유지한다. 근거만 Opus 4.8 → Opus 5 로 갱신.

## 5. 출력 길이

Opus 5 는 기본 응답과 **디스크에 쓰는 산출물**(리포트·마크다운 문서·저널)이 이전 모델보다 길다. `effort` 를 낮춰도 가시 출력 길이는 안정적으로 줄지 않는다 — **길이는 프롬프트로 조절한다.**

- 파일을 생성하는 skill (`journal`, `session-handoff`, `feedback-send`, 리포트류) 은 분량 지침을 명시한다: 실질을 담되 채우기 섹션·중복 요약·보일러플레이트로 늘리지 않는다
- 자기 정정을 길게 서술하지 않는다 — 사용자의 코드·결론·판단을 바꾸는 오류만 정정하고 넘어간다
