## 이 표가 뒤집는 것

**「매 턴 상시 주입 ≈99KB 가 남은 비용이다」는 틀렸다.** 상시 주입(시스템 프롬프트 + 도구
스키마 + CLAUDE.md + 규칙 전부)은 **첫 턴 cacheRead = 약 27K** 이고 그게 전부다 —
중앙값의 **5%**. 규칙을 다이어트해도 나머지 95%는 그대로다.

**95%는 세션 안에 쌓인 도구 결과**다. 한 번 들어온 명령 출력·파일 내용은 지워지지 않고
그 뒤의 **모든 턴에서 다시 읽힌다.** 캐시 적중 99%는 「싸게 읽는다」이지 「적게 읽는다」가 아니다.

## 규칙

1. **판단 근거로 쓸 출력은 파일로 받고 필요한 부분만 읽는다** — `cmd > log 2>&1; RC=$?` 뒤
   `tail -20 log`. 이건 새 규칙이 아니라 `agent-evidence.md` §C 가 이미 처방한 형태이고,
   **그 처방에 비용 근거가 붙은 것**이다. 자르지 말라는 것은 «판정» 이고, 상주시키지 말라는
   것은 «전문» 이다 — 파일이 둘을 동시에 만족시킨다.
2. **출력 상한을 낮게 둔다** — 허브 `bashOutputMaxChars` = **30,000**
   (100,000 에서 내림 · 2026-09-16). 100K 문자 ≈ **25K 토큰**이 한 번의 명령으로 상주하고,
   500턴 세션이면 그 하나가 **12.5M 캐시 읽기 토큰**이 된다.
   배경 작업은 상한이 아니라 **형태**로 막는다 — Claude Code 2.1.277 이 `TaskOutput` 을 없애
   `taskOutputMaxChars` 는 효과가 없다. 출력은 파일로 남으니 `Read` 로 **필요한 부분만** 읽는다.
   ⚠ 상한은 **보이는 절단**이다(러너가 잘렸다고 말한다). 조용한 절단이 아니므로 증거 규율과
   충돌하지 않는다 — 다만 잘린 출력을 **전문으로 읽지 않는다**(파일로 다시 받는다).
3. **긴 세션 자체가 비용이다** — 2,505턴 세션의 후반부는 턴당 700K+ 를 읽는다.
   작업 단위가 끝나면 세션을 끊는 것이 다이어트보다 효과가 크다.
4. **큰 리포트 도구에는 `--json <path>` 나 리다이렉트를 먼저 쓴다** — `model-usage` ·
   `census:fleet` · `builds:sweep` 류. 2026-09-16 에 `model-usage` 를 리다이렉트 없이 돌려
   한 턴에 수천 토큰을 상주시킨 실측이 이 규칙의 계기다.
5. **턴마다 기다리지 않는다** — 게이트·배포·로그인 승인처럼 오래 걸리는 것은 전경 호출 한 번(≤10분)
   또는 `run_in_background` + 완료 알림으로 기다린다. sleep·tail·상태 조회를 여러 턴에 나눠 되풀이하면
   **그 턴마다 컨텍스트 전체를 다시 읽는다**(2026-09-23 실측: 대형 세션 3개에서 대기 353턴 ≈ 2.2억 토큰 —
   athsra 로그인 상태 조회 129회 포함).
6. **압축 창은 400K 다**(ADR-029 · `autoCompactWindow` 기본값). 1M 모델의 자동 기본값(~967K)까지 가면
   턴당 평균 65만 토큰을 다시 읽었다. 60%·85% 를 처음 넘으면 게이지(`user-prompt-context-gauge.ts`)가 한 줄 알리고,
   압축 직후엔 재개 카드(`session-start-compact-resume.ts`)가 정본 파일 자리를 다시 준다. 작업 단위가 끝나면
   `/modfolio-moon` → 새 세션 `/modfolio-sun` · 원격에서 새 세션이 불편하면 `/compact` 로 같은 세션을 이어간다.

## 이 규칙이 못 보는 것

- 상주량을 줄이는 것과 **맥락을 잃는 것**의 경계는 게이트가 못 잡는다. 잘린 출력을 근거로
  단정하는 것은 여전히 증거 규율 위반이다.
- 서브에이전트 위임은 상주를 **분리**하지만(자기 컨텍스트에서 돈다) 보고서가 돌아오면
  그만큼 다시 상주한다. 위임이 공짜가 아닌 이유다.
