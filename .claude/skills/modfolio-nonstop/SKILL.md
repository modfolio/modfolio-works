# /modfolio-nonstop — 목적을 달성할 때까지 멈추지 않는 자율 개발

> 오너 지시(2026-09-07 · 원문 비공개 — _quotes.md#SK-06): 질문 없이 계속 작업한다 · 판단은 항상 정공법 · 분기마다 웹서치와 재계획 · 오너가 클릭하지 않아도 진행 · «계속하겠습니다» 로 멈춰 서지 않는다 · 압축돼도 유실되지 않게 todo 를 md 에 기록하며 진행한다.

> 오너 정정(2026-09-25 · 원문 비공개 — 허브 원장 `knowledge/runs/20260925-eco-close.md` §결정): nonstop 은 **루프가 아니라 목적 달성**이다.
> 계속 작업을 이어가는 법칙은 그대로이고 리뷰·확인도 하지만, 목적을 달성하기 전에는 멈추지 않으며 **목적 달성을 최우선으로 개발을 쭉 이어간다.**

## 목적 달성 — 루프가 아니다

- **종료 조건은 목적이다.** 헌장의 받아들임 검사가 실제로 통과하고 그 출력이 원장 §매듭에 인용될 때 끝난다. TODO 가 비었다·라운드를 다 돌았다·재계획 주기가 왔다는 종료 조건이 아니다.
- **개발이 먼저, 검증은 곁에서.** 게이트·리뷰·배포 확인처럼 기다리는 일은 배경으로 돌리고 원장 «배경 검증» 칸에 적는다. 그동안 **다음 개발 항목을 다른 워크트리에서** 진행한다(검증 중인 트리는 건드리지 않는다 — 한 작업 공간에 작성자 하나). 결과가 오면 그때 반영한다.
- **검증은 통합 지점에 모은다.** 반복은 좁은 게이트(`gate:quick`), 독립 리뷰·풀 게이트는 통합(push·게시) 직전 한 번. 리뷰·게이트 실패는 멈춤 사유가 아니라 **다음 TODO** 다(원인 수정 → 재측정). 계측기(리뷰 도구·게이트)가 틀린 답을 내면 **계측기를 고친다**.
- **오너에게 넘기는 것은 넷뿐이다** — 파괴·지출·외부 발신·비가역. 설계 갈림·리뷰 처분·라운드 한도 판단은 정공법으로 스스로 정한다(2026-09-25 실측: 리뷰 P1 처분을 오너 대기로 넘기고 턴을 끝냈다 — 위반).

이 스킬은 **행동 계약**이다. 절차를 문자 그대로 밟지 말고 목표·제약으로 읽는다(Fable 5.1).
검증된 원형 = pdgd `plans/loop-260907.md`(24h 무인 루프 원장).

## 시작 — 원장을 연다 (없으면 만들고, 있으면 정독한다)

```bash
bun run modfolio:nonstop -- new <slug> --goal "<오너 원문 그대로>"   # 원장 생성 + .modfolio-nonstop-active 포인터
bun run modfolio:nonstop -- status                                  # 🔴 지금 상태 + 열린 TODO + 재계획 예정
bun run modfolio:nonstop -- tick "<매듭 요약> (<커밋>)"                # 매듭 1개 = 게이트 초록 + 커밋/푸시 뒤 한 줄
bun run modfolio:nonstop -- close "<사유>"                          # 종료·대화형 전환 — 모드 칸 «종료» + 포인터 삭제
```

원장 위치: 허브 `knowledge/runs/<yyyymmdd>-<slug>.md` · 멤버 `plans/modfolio-nonstop-<yyyymmdd>-<slug>.md`. **압축 후 첫 행동 = `.modfolio-nonstop-active` 가 가리키는 원장 정독.** 요약과 원장이 어긋나면 **원장이 옳다.** 원장은 «지금 어디까지 왔나» 만 담는다 — 설계는 계획 파일(`~/.claude/plans/…`)에 있다.

원장의 고정 구획: `## 🔴 지금 상태`(표: 모드 · 목적까지 · 마지막 커밋/게이트 · 미커밋 · 배경 검증 · 처리 중 · 오너 대기 · 다음 할 일) · `## 헌장`(오너 원문) · `## 절대 규칙` · `## TODO`(`[ ]` 미착수 `[~]` 진행 `[x]` 완료 `[→]` 이월) · `## 매듭`(append-only · 시각·커밋) · `## 결정`(갈린 자리와 근거).

## 절대 규칙 (예외 없음)

0. **턴을 끊지 않는다.** 보고는 도구 호출 사이의 짧은 산문. 매듭이 끝나면 **다음 도구 호출을 같은 턴에** 낸다. 「계속하겠습니다」「이어가겠습니다」로 턴을 끝내는 것은 **이 스킬의 위반**이다 — 그 문장을 쓸 자리에는 도구 호출이 온다.
1. **질문하지 않는다.** 갈리면 정공법(`fundamentals-first.md`)으로 정하고 `## 결정` 에 근거를 적는다. 오너만 정할 것(파괴·지출·외부 발신·되돌릴 수 없는 것)은 **묻지 않고 `오너 대기` 칸에 적은 뒤 다른 항목으로 계속**한다.
2. **기다려야 하면 기다리는 도구를 쓰고, 기다리는 동안 개발한다.** 배경 작업은 완료 알림을 기다리고 **출력 파일을 `Read`** 로(`TaskOutput` 은 2.1.277 제거 · 알림 exit code 는 래퍼의 것이라 명령에 심은 `GATE_EXIT=` 마커를 읽는다), 조건 대기는 `Monitor` 로, 외부 상태(CI·배포)는 폴링으로 — 사람처럼 앉아 있지 않는다. 기다리는 동안 **다음 개발 항목을 다른 워크트리에서** 진행한다 — 검증이 개발을 세우면 이 스킬의 위반이다.
3. **턴을 넘어서는 재개는 `ScheduleWakeup` 으로 스스로 깨어난다 — 단, 오너가 이 스킬을 열며 준 목표(원장 `## 헌장`) 안에서만.**
   승인의 단위는 **연 시점의 헌장**이지 원장의 TODO 목록이 아니다. TODO 는 헌장을 잘게 나눈 것이고,
   재계획(규칙 4)이 그 목록을 고쳐 써도 헌장은 고쳐지지 않는다 — 내가 방금 적은 TODO 는 깨어날
   근거가 아니다(review 2026-09-22: TODO 를 기준으로 삼으면 재계획이 승인을 무한히 갱신한다).
   헌장으로 소급되지 않는 항목은 새 목표이므로 만들지 않고, 헌장 안의 TODO 가 비면 깨어나지 않으며,
   오너가 중단·자동화 해제·새 목표 금지를 말했으면 그 지시가 우선한다(우회 금지). 이 규칙이 규칙 0
   (턴을 끊지 않는다)의 기계적 보장이다. 현재 도구에 `ScheduleWakeup` 능력이 없으면(도구 이름이
   아니라 도구 목록으로 확인) 원장에 «재개 필요 · 시각» 을 적고 턴을 끝내는 것이 위반이 아니다.
   재개 시 원장을 먼저 읽는다.
4. **매듭 5개마다 재계획 — 헌장 안에서.** `bun run modfolio:nonstop -- status` 가 «재계획 예정» 을 내면: 계획 파일을 다시 읽고 · 허브면 `plan:build`/`currency:probe`, 어디서든 WebSearch 로 그 항목의 최신 1차 출처를 확인하고 · TODO 를 고쳐 쓰고 · `## 결정` 에 «무엇이 바뀌었나» 한 줄. 재계획은 헌장 범위 안에서 TODO 를 나누고·순서를 바꾸고·버리는 것이지 목표를 붙이는 것이 아니다 — 헌장 밖에서 발견한 일은 `## 결정` 에 «후속 후보» 로 적어 오너에게 남긴다. 재계획이 «변경 없음» 이어도 그 사실을 적는다.
5. **게이트 초록 뒤에만 커밋 · 커밋 뒤에만 매듭.** 결과 판정은 exit code(파이프 뒤 `$?` 금지). 커밋은 내가 만진 경로만 스테이징(`add -A` 금지 — 남의 미완성 작업을 섞지 않는다).
6. 이 repo 밖은 **읽기만**. 허브에서만 Orbit Writ 로 한 repo 씩. 파괴 명령(`--force`·`--no-verify`·`reset --hard`·`rm -rf`)·지출은 이 스킬 안에서도 오너 대기.
   ⚙ **무인 구간에서는 창이 뜨면 대응하는 것이 아니라 창이 뜰 수 없게 한다** — 승인 창이
   뜨는 순간 무인은 끝나고, 오너는 폰이라 그 창을 누를 수 없다. 무인 명령은
   `DISPLAY`·`WAYLAND_DISPLAY`·`DBUS_SESSION_BUS_ADDRESS`·askpass 를 **해제**하고
   `GIT_TERMINAL_PROMPT=0` · ssh `BatchMode=yes` · `ATHSRA_TOKEN` 주입으로 돌린다
   (modfolio-pay 2026-09-14 실측 — keyring 없이 athsra 주입 성공. 원인은 WSLg
   gnome-keyring 으로 **추정**이며 미확정이지만, 처방은 원인 확정을 기다리지 않는다).
7. **0건·무반응·판정 불능은 결론이 아니다** — probe·키·전제부터 의심하고(양성 대조), 그래도 안 되면 원장에 «미검사» 로 적고 다음으로.
8. 하루에 한 번 이상 `/debrief`(원칙 캡처) · 끝나면 `/modfolio-moon`.

## 리듬 — 개발 흐름 하나, 검증 흐름 하나

```
개발:  원장 정독 → 다음 TODO → 구현(좁은 게이트로 반복) → 커밋 → tick → 다음 TODO → …
검증:  (통합 지점마다) 풀 게이트·독립 리뷰를 배경으로 → «배경 검증» 칸 → 결과가 오면
       통과 = 통합·게시 · 실패 = 새 TODO(원인 수정 → 재측정) — 개발 흐름은 서지 않는다
목적:  헌장의 받아들임 검사가 전부 통과(출력 인용)할 때만 종료. 매듭 5개마다 «목적에 가까워졌나» 로 재계획
```

종료 조건(목적 달성 또는 오너 «멈춰»)이 오면 `## 🔴 지금 상태` 를 최종으로 고치고 `/modfolio-moon` 으로 인계한 뒤 `bun run modfolio:nonstop -- close "<사유>"` 로 포인터를 닫는다(오너가 대화형으로 돌려도 같다). 그 전에는 **이 턴이 끝나지 않는다.**
