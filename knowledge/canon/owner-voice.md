# Owner Voice — 발화에서 성향을 만든다

> **이 축의 목적은 저장이 아니라 성향이다.** 오너의 원문을 보관하는 것이 목적이면 대화
> 로그로 충분하다. 목적은 **다음 세션이 같은 사람으로서 판단하는 것**이고, 그래서 모든
> 항목은 «그래서 무엇을 다르게 하는가» 를 행동으로 적는다.

## canon 과 무엇이 다른가 — 섞으면 충돌을 못 푼다

| | 어디서 나오나 | 틀렸을 때 |
|---|---|---|
| **canon** | **실측** — 명령을 돌려 나온 것 | 다시 재면 드러난다 |
| **voice** | **발화** — 사람이 말한 것 | 다시 잴 수 없다. 물어봐야 한다 |

둘을 한 문서에 섞으면 «이 사람이 그렇게 말했다» 와 «측정해 보니 그렇다» 가 구분되지 않고,
그러면 부딪힐 때 **무엇이 이기는지 정할 수 없다.** 그래서 분리하고 우선순위를 못박는다:

> ### 🔒 **canon(실측) > voice(발화)**
> 오너가 «그렇게 해» 라고 해도 **실측이 반대면 그 사실을 말하고 진행한다.**
> voice 는 판단 **성향**이지 실측을 이기지 않는다. 이건 불복이 아니라 오너가 요구한
> 것이다 — 「판단이 갈리는 자리는 드러내고 진행한다」가 voice 항목 자체에 있다.

## 항목의 형식 — 넷, 전부 필수

`modfolio-notify` 가 먼저 만든 형식을 그대로 쓴다. **두 형식이 생기면 그중 하나가 언젠가 갈린다.**

```markdown
### <짧은 제목>

- **observed**: 2026-08-05
- **quote**: «오너의 발화 원문 그대로»
- **scope**: fleet | <repo>
- **applies**: 그래서 무엇을 다르게 하는가 — **행동으로**
- **status**: active | superseded-by <제목>
```

### ⚠ `quote` 없으면 등재하지 않는다

> **quote 를 못 적는 항목은 관측이 아니라 추론이다.** (notify, 2026-08-05)

이게 이 말뭉치의 품질을 혼자 결정한다. 실측된 실패 형태:

- *"(전 세션 관측 — …)"* · *"(2026-07-29 실측 — …)"* 처럼 **괄호 서술**로 대체
- 인용문은 있는데 **그 인용이 주장을 뒷받침하지 않는** 경우(다른 주제의 발화를 붙임)
- **이미 canon·전역규칙에 있는 사실**을 발화인 것처럼 옮겨 적음 → 그건 voice 가 아니다.
  그쪽이 정본이고, 여기 사본을 두면 둘이 갈린다

원문을 못 찾겠으면 **적지 말고 물어본다.** 지어낸 인용은 나중에 «정말 그렇게 말했나» 를
확인할 수 없게 만들고, 이 유니버스는 「인용은 증거가 아니다」를 이미 비싸게 배웠다.

### ⚠ `applies` 는 행동이어야 한다 — 실증

notify 의 V-001(*"내가 웹에서 확인할 수 있어야해"*)이 `applies` 를 행동으로 적게 한 덕에
실제로 코드가 바뀌었다: `verify:deploy` 의 마지막 검사가 «CF 가 무엇을 빌드했나» 에서
**«라이브 워커가 자기 커밋을 무엇이라고 말하나»** 로 바뀌고 `/healthz` 에 `commit` 이 생겼다.

*"완료는 커밋이 아니라 확인 가능"* 이라고만 적었으면 아무 일도 안 일어났을 것이다.

### 모순은 «추가» 가 아니라 «승계»

새 발화가 옛 항목과 부딪히면 옛 것을 `status: superseded-by <제목>` 으로 바꾸고 **남긴다.**
지우지 않는 이유는 **판단이 바뀐 시점 자체가 정보**이기 때문이고, 그냥 쌓기만 하면
서로 모순되는 목록이 되어 아무 지침도 못 준다.

⚠ **조건부 선호는 모순이 아니다.** *"자리에 있을 땐 묻고, 무인일 땐 묻지 마라"* 는 하나의
항목이다. 한쪽만 기억하면 **매번 틀리므로** 반드시 두 조건을 같이 적는다.

## 무엇을 쌓고 무엇을 안 쌓는가

| 쌓는다 | 안 쌓는다 |
|---|---|
| 재사용되는 지시 — «이렇게 해줘 / 하지 마» | 일회성 작업 — «이 파일 고쳐줘» |
| 선택의 근거 — «이게 더 낫다» + 왜 | 이미 canon·contracts·rules 에 있는 사실 |
| 조건부 선호(모드·상황에 따라 달라지는 것) | 그때그때의 상태 보고 |
| 금지와 그 이유 | 에이전트가 추론한 «아마 이런 뜻일 것» |

**판별 질문**: *"다음 세션이 이걸 모르면 같은 것을 또 물어보거나, 다르게 판단하는가?"*
아니라면 쌓지 않는다 — **중복은 축적이 아니라 희석**이다.

## 🔒 등재 금지 — 이 말뭉치는 공개된다

`knowledge/` 는 `@modfolio/harness` 타르볼에 실리고, canonical 레지스트리
`pkg.modfolio.io` 는 **익명 읽기가 가능**하다(CLAUDE.md — *"anon-read 라 소비에 토큰 불요"*).
즉 **원문 보존이 곧 공개**다. 다음은 발화에 있어도 등재하지 않는다:

- 시크릿·토큰·자격증명 (Class 0 — `secrets-policy.md`, 코퍼스 전면 금지)
- 개인정보 — 오너 본인 것을 포함해 주소·연락처·계좌·주민번호류
- **제3자**의 실명·평가·사적 정보 (오너는 자기 발화의 저자지만 제3자의 저자는 아니다)
- 계약·법적 분쟁·미공개 사업 수치

필요하면 **판단만 남기고 대상을 지운다** — «X 사와의 협상에서는…» → «외부 협상에서는…».
그렇게 하면 quote 가 원문이 아니게 되므로, **그 사실을 항목에 명시**한다(`quote` 옆에
`(대상 익명화)`). 조용히 고치지 않는다.

## 누가 쓰고 누가 정본을 갖는가

```
각 repo 세션  →  자기 관측을 자기 repo 에 쌓는다  →  scope: fleet 만 허브로 발신
허브          →  정본(knowledge/voice/) + 중복 판정 + 승인 게이트
```

- **허브가 정본**이고 **중복 판정도 허브 몫**이다. 8개 repo 가 각자 관측하면 같은 발화를
  여러 번 받는다
- **각 repo 가 자기 관측을 쌓는 것은 막지 않는다.** 오너는 각 repo 세션에서도 말하고
  **그 발화는 그 세션에만 존재**한다 — 허브가 볼 수 없는 것을 허브가 정본화할 수 없다
  (`fact-ownership.md` 와 같은 축)
- 발신 배치 단위는 **세션**이다. 관측 하나마다 노트를 보내면 수신함이 찬다
- ⚠ **자기 repo 관측을 허브 파일에 직접 쓰지 않는다.** 2026-08-05 에 그 일이 실제로
  일어났고(형제 세션이 허브에 직접 커밋), 그쪽이 자진 보고했다. 경로는 피드백이다

## 승격에는 게이트가 있다 — 자동 등재는 없다

`knowledge-sovereignty.md` §2 가 **«자동 승격은 없다»** 를 못박는다. 이 말뭉치도 예외가 아니다.

```
대화 중  →  발화 캡처 → 후보로 적재 (조용히)
턴 끝    →  「이번에 새로 나온 것 N건 … 올릴까요 [전부 / 골라서 / 나중에]」
승인 후  →  knowledge/voice/*.md  →  sync  →  30 repo
```

- **동석 모드**(오너가 자리에 있다): 턴 끝에 **에이전트가 대화 안에서 직접 묻는다**
- **무인 모드**(밤샘·원격): 후보만 적재하고 **묻지 않는다.** 다음 동석 세션에서 일괄 제시
- ⚠ **훅으로는 못 만든다** — `Stop` 훅은 사용자 입력을 받을 수 없다(실측 2026-08-05:
  `{"decision":"block"}` 은 **모델**에게 가고 `exit 2` 는 하드 차단뿐). 훅이 할 수 있는
  것은 **«미승인 후보 N건» 리마인드 1회**까지다
- 미승인 후보 파일은 `_` 접두(`knowledge/voice/_candidates.md`)이고 **동기화 제외**다.
  승인 전 발화가 30 repo 로 나가면 그것이 곧 게이트 없는 승격이다

## 배선 — 어디에 두면 실제로 읽히는가

| 자리 | 도착하나 | 비고 |
|---|---|---|
| `knowledge/voice/*.md` | ✅ | harness-pull 이 멤버로 동기화(3.55.0+) |
| `knowledge/global.md` 의 `SYNC_ESSENTIALS` 구간 | ✅ | 각 멤버 **CLAUDE.md** 로 들어간다 |
| `.claude/rules/` | ❌ | `harness-pull` 이 상류 사본으로 갈아 끼운다 — **다음 pull 에 사라진다** |
| 허브 git 만 | ❌ | 멤버는 `node_modules/@modfolio/harness` 를 읽는다. **게시돼야 닿는다** |

⚠ 세 번째와 네 번째는 가설이 아니라 실사건이다. 3.50.0 autoPull 이 athsra 의
`.claude/rules/` 두 파일에서 각각 46줄을 지웠고 리포트는 «성공» 이었다.

⚠ **`global.md` 인라인은 최소로.** 그 구간은 **모든 멤버의 매 턴 컨텍스트**를 먹는다.
전문을 넣지 않고 (a) 포인터 (b) 우선순위 (c) **조건부 항목만** 인라인으로 둔다 —
조건부는 한쪽만 기억하면 매번 틀리므로 포인터로는 부족하다.

| **적재** — consent 게이트 · ingest · 재조정 · 원장 | **visualize** | 말뭉치·consent 가 그 repo 제품 표면 (ADR-015) |

되므로 sibling 파일이 0개다 — 배포되는 것이 없다. 근거는 **배포 방식이 아니라 시점**이다.

⚠ **다른 repo 가 자기 관측을 쌓는 것은 이 표와 무관하다.** 그건 계속 하고, `scope: fleet`
만 허브로 보낸다(§소유). 표가 정하는 것은 **레일을 누가 짓는가**다.

## 미결

1. **주입 레일** — Muse 가 이미 `UserPromptSubmit` 으로 top-k 를 넣는다(`MAX_BULLETS = 5`).
   voice 를 같은 레일에 태우면 **예산 경쟁**이 생긴다(Muse 카드가 밀린다). 별도 레일인지
   합치는지 미정
2. **`EXTRA_HOOK_POSITIONS` 갭** — `harness-lock.json` 의 `extraHooks` 로는 `UserPromptSubmit`
   을 배선할 수 없다(허용 위치가 `pre-push-guard`·`pre-commit-guard` 둘뿐).
   즉 **profile 에 없는 이벤트는 멤버가 자기 결정으로 영영 못 쓴다**(infra 제보 2026-08-05).
   위 소유표는 머신 레벨 배선을 쓰므로 이 갭에 막히지 않지만, 갭 자체는 별도로 남아 있다
