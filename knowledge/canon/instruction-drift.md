# 지시문 드리프트 — 규칙을 산문이 아니라 구조로 지킨다

> **오너 질문 (2026-08-23)**: *"계속 새로운 기술 스택 도입과, 버전 업데이트, 그리고
> 이어지는 다양한 세션들에서 AI와 바이브코딩 작업을 할 때, 규칙이나 법칙 그리고 이러한
> 세팅이 계속 어긋나거나 하는 것이 걱정이야. 그때그때 세션의 AI가 절대적으로 잘 지킬 수
> 있는지, 그런 걸 위한 검증된 방법이 있는지."*

**답: 못 지킨다. 그리고 그건 모델의 결함이 아니라 산문의 성질이다.** 아래는 우리 실측이다.

## 1. 우리 자신의 실측 — 걱정이 가설이 아니었다

```
2026-07-26  A/B 실험 직후 정리   CLAUDE.md + 상시 규칙   55,426 bytes
2026-08-23  4주 뒤                                      206,964 bytes    3.7배
```

증가의 대부분이 한 파일이었다:

```
.claude/rules/agent-evidence.md   2026-07-04    3,068 bytes
                                  2026-08-17  137,065 bytes   ← 44.6배 / 6주
```

그 파일은 `UNIVERSAL_RULES` 라 **30+ repo 의 매 세션**에 들어간다.

**⚠ 두 가지가 이 사건을 규칙으로 만든다.**

1. **드리프트가 드리프트를 막으려고 만든 문서 안에서 일어났다.** 내용은 전부 진짜 실측이었다 —
   틀린 것은 **운반 방식**이었다.
2. **아무도 결정하지 않았다.** 매 세션이 좋은 교훈을 찾으면 append 했고, 아무도 지우지
   않았고, **크기를 보는 것이 없었다.** 이 저장소가 31개 게이트를 굴리면서 자기 지시문의
   성장에는 게이트가 **0개**였다.

그리고 우리는 **이 질문에 이미 답을 갖고 있었다.** 2026-07-26 통제 실험(문항 24 × arm 2,
블라인드 채점, 격리 프로세스):

```
full (96KB 하네스)   rubric 0.938 · core 23/24 · over-reach 2
lean  (1KB 불변원칙)  rubric 0.979 · core 24/24 · over-reach 1
better 3 / worse 0 · Wilcoxon p=0.109 (미유의)
```

실험 전체의 **유일한 core 오답이 full arm 에서** 나왔다(매몰비용 논리로 롤백을 회피).
결론은 *"이득은 미측정, 비용은 확정"* 이었고 그날 102KB → 61KB 로 잘랐다.
**그 결론을 내고 4주 만에 3.7배가 됐다.** 원자료 = `journal/20260726-harness-context-ab.md`.

## 2. 업계도 같은 방향이다

**핵심 인용** (대조 2026-08-23):

- 580개 instruction 파일(568 repo, 8,222줄) 중 **기계 검증 가능한 규칙은 309개 = 3.8%**.
  파일의 **74%(430/580)는 검증 가능한 규칙이 0개**.
  1차 출처: https://dev.to/moonrunnerkc/we-parsed-580-ai-instruction-files-96-of-the-content-cant-be-verified-4cg5
- *"AI 는 몇 달 걸리던 아키텍처 열화를 **오후 하나에** 만든다"* — 한 세션이 파일 수십 개의
  경계를 넘기 때문. 1차 출처: https://techdebt.guru/ai-architecture-drift/
- 명시적 지시 강화는 **일관성을 조금 올릴 뿐 비대칭 목표 드리프트를 제거하지 못했다**.
  1차 출처: arXiv 2603.03456
- 합의된 처방: *"아키텍처 규칙을 **워크플로로** 옮겨라 — 프롬프트를 길게 만들지 말고."*
  1차 출처: https://lukasniessen.com/blog/12-architecture-fitness-functions/

⚠ 이 인용들이 참임을 증명하는 것은 링크와 대조 날짜이지 이 문서가 아니다.
그리고 **한 사례는 명시적으로 미검증이다** — *"5개월 100% Claude Code, 드리프트 0"*
(https://dev.to/teppana88/5-months-100-claude-code-zero-architectural-drift-i6e) 은
컴파일·테스트·커버리지 80%만 **측정**했고 「드리프트 0」은 **주장**이다. 그 글에서 우리가
가져온 것은 결과가 아니라 **기제**(규칙 파일 잠금)다.

## 3. 처방 — 강한 순서대로 세 층

| 층 | 형태 | 산업 레퍼런스 | 우리 구현 |
|---|---|---|---|
| **1. 불가능하게** | 팀 간 통신은 인터페이스로만 · *"no back-doors whatsoever"* | Bezos API mandate (2002) → AWS | `assembly-law` 3표면 · [[judgment-core]] (**I/O 가 없으면 남의 도메인에 닿을 수단이 없다**) · 패키지 경계 |
| **2. 자동으로 잡기** | fitness function — 경계·의존을 테스트로 | Nx tags · dependency-cruiser · ArchUnit | `quality:all` · `release:gate` · `pre-*-guard` 훅 |
| **3. 사람** | 골든 패스 — *"말해주는 게 아니라 대신 해준다"* | Netflix Wall-E · Spotify Golden Path | 스캐폴더 (미구축) | (실측 2026-08-25 — 스캐폴더성 npm script 0건)

**1층이 가장 강한 이유**: 순응이 필요 없다. [[judgment-core]] 의 순수성은 «지키자» 가
아니라 «할 수단이 없다» 다.

## 4. 교훈 라우터 — 새 교훈은 산문에 append 하지 않는다

이것이 137KB 사건의 **근본 수정**이다. 좋은 교훈을 버리는 것이 아니라 **갈 곳을 정한다**:

```
① 기계로 검사할 수 있는가         → 게이트 (scripts/ci/)          가장 강함 · 고정비 0
② 재인식 가능한 판단 휴리스틱인가  → /debrief → Muse              top-k 주입 · 고정비 0
③ 둘 다 아닌 실측 서사인가        → evidence-cases-*.md           온디맨드 · 고정비 0
```

**셋 다 매 턴 비용이 0이다.** 산문에 append 하는 것만이 30+ repo × 매 턴을 청구한다.

> Muse 는 이미 **1,334 bullet · 635KB** 를 갖고 있고 프롬프트당 ~2KB 만 주입한다.
> 우리는 그 기계를 지어 놓고 **가장 큰 지식 파일을 그 밖에서** 굴리고 있었다.

## 5. 집행 — 두 게이트

### `context:budget` — 상시 주입 산문에 상한

`.claude/rules/*.md` 는 `paths:` 프론트매터가 있으면 경로 스코프, 없으면 **상시 주입**이다
(양성 대조 2026-08-23: 이 휴리스틱이 뽑은 7개 = 실제 세션 시스템 프롬프트의 7개).

```
총 상한     110,000 bytes     현재 98,290
단일 파일    40,000 bytes     현재 최대 CLAUDE.md 34,199
```

⚠ **상한을 올려서 통과시키는 것은 처방이 아니다.** 「예산이 늘어난 기록」은 게이트가 아니다.

**과거에 적용해 봤을 때 최초 발화일 = 2026-08-04.** 즉 게이트가 있었다면 **19일 일찍**
울렸다. 실제로는 아무도 몰랐다.

### `pre-law-guard` — 법·규칙 파일의 즉흥 편집 차단

잠기는 것: `.claude/rules/**` + `tier: law` canon(계산됨). **읽기는 절대 안 막는다.**

```
Edit  .claude/rules/x.md            → exit 2
Bash  sed -i … .claude/rules/x.md   → exit 2
Bash  bun run some-script.ts        → exit 0   ← 런타임에 정한다. 원리적 한계
```

마지막 줄이 **위치의 한계이지 넓혀서 고칠 결함이 아니다** — 넓히면 허브 자신의 fleet
도구를 벌한다. **초록을 «법이 안 바뀌었다»의 증거로 읽지 않는다.**

**예외는 한 마디면 열린다** — 오너가 «고쳐» 라고 하면 에이전트가 **스스로** 실행한다:

```sh
bun run law:writ grant --paths <경로> --reason "오너 지시 — …"
bun run law:writ revoke
```

터미널도 브라우저도 인증도 없다. GitHub push ruleset 을 **의도적으로 쓰지 않은** 이유가
그것이다 — 권한 서버를 두면 «당신이 로그인하세요» 경로가 생기고, `agent-auth-flow.md` 가
그것을 금지한다.

### ⚠ Orbit Writ 가 남긴 결함 셋 — 여기서는 처음부터 안 만들었다

2026-08-08 실측: `orbit:grant <repo>` 한 줄에 **31 repo 가 열렸다.**

1. **범위 누적** — `[...state.scope, repo]`. 갈린 방향이 **권한을 넓히는 쪽**
2. **감사 불일치** — 실제 권한과 **다른 값**을 기록. 사후 재구성 불가
3. **해제가 안 비움** — `active:false` 만 바꿔 다음 발급이 오염된 채 출발

→ `law:writ` 는 grant 가 **대체**하고, revoke 가 **범위를 비우고**, 감사에 **실제로 쓴
값**을 적는다. 회귀 테스트가 **소스를 읽어** 누적 패턴 부재를 단언한다 — 성질 서술만으로는
구현이 다시 누적으로 돌아가도 통과한다.

## 6. 이 문서가 말하지 **않는** 것

- **«산문이 해롭다»** — 아니다. A/B 는 p=0.109 로 미유의였다. 말하는 것은
  **«더 넣는 것이 좋아진다는 증거가 두 라운드 모두 없었고, 비용은 확정»** 이다
- **«규칙을 지우자»** — 아니다. 137KB 는 한 글자도 안 버렸다. **옮겼다**
- **«이제 드리프트가 없다»** — 두 게이트는 **파일 크기와 즉흥 편집**만 본다.
  프로그램이 쓰는 것, 내용의 옳음, 멤버 repo 의 로컬 규칙은 **미검사 축**이다
